# 学生状态判断与提示分级

> 第 2 组 · AI 巩固对话模块 · 2026-10-29
> 说明系统怎么判断"学生现在处在哪一步"，以及判断之后给哪一种提示。
> 对应汇报 PPT 第 5 页（业务流程 2）、第 9 页（活动图与规则）、第 11 页（状态图）。
> **2026-11-07 更新：** 对话规则已改成"不直接给解"，现行规则见下面的规则表和 `docs/计划-AI对话重新设计.md`。标了"第一版"的章节和提示词 v1 的内容只作历史记录；现行提示词是 `dialogue_turn_v3`、`topic_draft_v3`。
> 代码位置：`DialogueService.send()` / `recount()` / `apply()`，`JudgementParser`，`DialogueRules`。

---

## 一、总览：分三层判断

```
学生的动作
   │
   ├─ 点了"我卡住了"按钮 ──────────────→ 直接判为"卡住"（不调模型）
   │
   └─ 打了一句话
        │
        ▼
   第 1 层：模型判断这一句是哪一类（6 种）+ 答到了哪几条要点
        │
        ▼
   第 2 层：程序复核（重新数要点、处理异常）→ 这一句的最终类型
        │
        ▼
   第 3 层：程序按"这个话题里累计发生过几次" → 学生现在在哪一步、系统做什么
```

| 层 | 谁来做 | 负责什么 |
|---|---|---|
| 第 1 层 | 大模型 | 听懂"这一句在说什么" |
| 第 2 层 | 程序 | 数清楚"一共答到了什么"，处理模型出错 |
| 第 3 层 | 程序（`DialogueRules`） | 根据累计次数决定"现在在哪一步、该做什么" |

## 二、第 1 层：模型判断"这一句是哪一类"

学生打的每句话都交给模型。提示词 `dialogue_turn_v3` 写清了 8 种类型的定义，模型必须从中选一种，并列出这句答到了哪几条要点（编号从 1 开始）。

| 类型 | 提示词里的定义 | 例子（话题：下边界取哪些值；要点 1 = 越过边界的 0，2 = 边界上的 1，3 = 边界内侧的 2，4 = 为什么测这里） |
|---|---|---|
| correct | 要点全部答到 | "0、1、2，0 应该被拒绝" |
| partial | 答到一部分 | "1 和 50 吧"（只答到要点 2） |
| wrong | 相关，但答错 | "测 50 就够了" |
| irrelevant | 和学习无关的话，如"哈哈"、表情、"今天吃什么" | "哈哈" |
| want_answer | 明确要答案 | "直接告诉我吧" |
| struggling | 表示不会、太难、没信心，但没有要答案 | "太难了" |
| clarify | 没听懂题目，或问题目里的词是什么意思 | "什么是下限？" |
| off_topic | 问和学习、软件有关但资料里没有的问题 | "白盒测试怎么做？" |

模型返回的格式固定为 JSON：

```json
{"type": "partial", "hit_points": [2], "reply": "1 选得好，那边界外面的值呢？"}
```

为了让模型判断得准，提示词里还给了它这些信息：
- 话题、情境问题、**带编号的要点**、依据资料；
- 程序状态：本话题已尝试几次、已用提示几次、**此前已答到的要点**；
- 最近 6 条对话；
- 并要求：如果"此前已答到的 + 这一句"已经覆盖全部要点，就判 correct。

**为什么这一层交给模型**：学生的说法千变万化（"1 和 50""一和五十""最小值和中间的"），用关键词很难判断，而理解自然语言正是模型擅长的。

## 三、第 2 层：程序复核

模型的判断不直接使用，程序先检查一遍。

### 3.1 异常情况

| 情况 | 程序怎么处理 | 代码 |
|---|---|---|
| 返回的不是 JSON | 视为失败，**这一句按 wrong 处理**，回复用预写提示 | `JudgementParser.parse()` 抛异常 → `send()` 的 catch |
| type 不在 6 种之内 | 同上 | 同上 |
| 调用超时 / 503，重试 2 次后仍失败 | 同上 | `OpenAiCompatibleClient.chat()` 抛异常 → `send()` 的 catch |
| 回复为空或超过 120 字 | 判断照用，但**不显示模型的回复**，改用预写提示 | `usable()` |

### 3.2 重新数要点（`recount()`）

```java
int n = topic.keyPoints().size();                                       // 要点总数
Set<Integer> all = hits(state);                                         // 之前已答到的
List<Integer> valid = j.hitPoints().stream().filter(i -> i >= 1 && i <= n).toList();   // 去掉越界编号
all.addAll(valid);                                                      // 合并
state.setHitPoints(join(all));                                          // 存回进度表

if (type 是 CORRECT / PARTIAL / WRONG) {
    if (all.size() == n)                     → CORRECT    // 合起来全齐
    if (type == CORRECT || 这句有新要点)      → PARTIAL    // 说全对但不齐；或说错但其实答到了新要点
}
否则照用模型的判断（IRRELEVANT / WANT_ANSWER / STRUGGLING / CLARIFY / OFF_TOPIC）
```

| 模型说 | 之前已答 | 这句答到 | 程序最终判 | 说明 |
|---|---|---|---|---|
| partial [2] | 无 | 2 | PARTIAL | 不齐 |
| partial [1, 3] | 2 | 1、3 | **CORRECT** | 合起来 1、2、3 全齐 |
| correct [1] | 无 | 1 | **PARTIAL** | 模型说全对，但只答到 1 条 |
| wrong [1] | 无 | 1 | **PARTIAL** | 模型说错，但其实答到了新要点 |
| wrong [] | 2 | 无 | WRONG | |
| correct [1, 2, 3, 7] | 无 | 1、2、3 | CORRECT | 7 越界，被去掉 |
| irrelevant [] | 2 | 无 | IRRELEVANT | 照用 |

最终类型存在学生消息的 `judged_type` 字段里，事后可以检查每一句被判成了什么；这一句对应的模型调用记在 `ai_call_id`，可以查到完整提示词和模型原始返回。

**为什么要复核**：答没答对决定学生能不能进入下一个话题，不能只凭模型一句话。数要点是确定的计算，交给程序更可靠。

## 四、第 3 层：程序判断"学生现在在哪一步"

### 4.1 进度表里记了什么

每个话题有一条 `dialogue_topic_state`：

| 字段 | 含义 | 什么时候变化 |
|---|---|---|
| `wrong_count` | 答错次数 | 这一句最终判为 wrong 或 partial 时 +1 |
| `stuck_count` | 卡住次数 | 点"我卡住了"，或这一句判为 struggling、want_answer 时 +1 |
| `irrelevant_count` | 无关次数 | 这一句判为 irrelevant 时 +1 |
| `hint_level` | 已给到第几级提示 | 没有进展时 +1，最高 L3（初始 -1 = 没给过） |
| `hit_points` | 已答到的要点 | 每次把新答到的要点并进去 |
| `result` | 话题结果 | 话题结束时定下来；还在聊时为空 |

### 4.2 规则（`DialogueRules`）

| 这一句 | 条件 | 系统做什么 | 话题结果 |
|---|---|---|---|
| correct | 要点全齐，之前没错、没卡住、没用提示 | 模型一句肯定，进入下一个话题 | SELF_CORRECT 自己答对 |
| correct | 要点全齐，其他情况 | 模型一句肯定，进入下一个话题 | HINT_CORRECT 提示后答对 |
| wrong / partial | 有新要点 | 模型肯定并追问，不升级 | — |
| wrong / partial | 没有新要点 | 升一级提示（L1→L2→L3），L3 之后一次给一条要点；要点都有了就出变式题 | — |
| want_answer | 作答过 | 同上：升一级，L3 之后给要点 | — |
| want_answer | 从没作答 | 模型提示，请学生先试；累计 3 次跳过，不给答案 | 第 3 次 SKIPPED_IRRELEVANT |
| struggling（说不会、太难，或点"我卡住了"） | 作答过 | 同上：升一级，L3 之后给要点 | — |
| struggling | 从没作答 | 模型鼓励并提示，最多到 L3，不给要点，不累计跳过 | — |
| irrelevant | 第 1 次 | 模型接话并提醒回到问题 | — |
| irrelevant | 第 2 次 | 跳过，不给答案 | SKIPPED_IRRELEVANT |
| clarify / off_topic | 不计次 | 模型解释题意，或说明资料里没有 | — |
| 到 8 轮上限 | 作答过进入变式；没作答过跳过 | 都不显示答案 | 没作答过 SKIPPED_IRRELEVANT |
| 变式题作答 | 答全 | 显示完整讲解 | REVEALED_APPLIED 讲解后会用 |
| 变式题作答 | 第 2 次仍没答全 | 显示变式答案和完整讲解 | REVEALED 讲解后仍不会 |
| 变式阶段 want_answer / irrelevant | 累计 3 次 | 结束，不显示答案 | REVEALED |
| 变式阶段 struggling | 不累计 | 继续提示，到 8 轮上限结束 | — |
| 跳过之后 | 连续跳过 2 个话题（且不是最后一个） | 暂停，等学生点"继续对话" | — |

阈值写在 `DialogueRules` 里（`MAX_HINT_LEVEL`、`MAX_TURNS`、`MAX_REFUSE`、`MAX_IRRELEVANT`、`MAX_TRANSFER_TRIES`、`PAUSE_AFTER_SKIPS`）。规则都有单元测试。

### 4.3 话题结束之后

1. 更新"连续跳过的话题数"：这个话题是跳过的就 +1，否则清零；
2. **是最后一个话题** → 整场对话结束（FINISHED），生成总结；
3. 否则切换到下一个话题；
4. 如果是跳过，并且连续跳过 ≥ 2 个 → **暂停**（PAUSED）；
5. 否则 AI 说出下一个话题的问题。

一次对话的状态只有 3 种：OPEN 进行中、PAUSED 暂停、FINISHED 结束。学生回答、卡住、换话题都不会改变它，一直是 OPEN。

## 五、用 Demo 那一次走一遍（第一版）

| 学生 | 第 1 层 模型判 | 第 2 层 程序复核 | 第 3 层 累计 → 阶段 | 显示给学生的 |
|---|---|---|---|---|
| "1 和 50 吧" | partial，[2] | 已答 {2}，不齐 → partial | 答错 1 次 → 追问 | 模型追问："你说对了 1 这个边界点。不过 50 属于中间值……" |
| "那 0 也要测……还有 2？" | partial，[1, 3] | 已答 {1, 2, 3} 全齐 → **改判 correct** | 错过 1 次 → 话题 1：**提示后答对** | 模型肯定 + 下一个话题的问题 |
| 点"我卡住了" | 不调模型 | — | 卡住 1 次 → 给提示 | 预写提示："想想程序员写判断条件时最容易犯什么错。" |
| "因为 50 太普通了" | wrong，[] | 无新要点 → wrong | 答错 1 次 → 追问 | 模型追问："没错，中间值确实很难发现逻辑漏洞……" |
| "直接告诉我答案吧" | want_answer | 照用 | 卡住累计 2 次 → 话题 2：**看了讲解** | 老师的讲解原文；最后一个话题 → 整场结束 → 总结 |

第 2 句是程序复核起作用的例子：模型说的是"部分对"，程序把前后两句合起来一数，三条要点都答到了，于是改判为答对。

## 六、判断之后给哪种提示（第一版，现行规则见 4.2）

学生会看到 5 种提示，由轻到重：

| # | 提示 | 谁写的 | 什么时候出现 | 例子（话题 1） |
|---|---|---|---|---|
| 1 | 简单问法 | 老师（AI 起草、老师确认） | 答非所问第 1 次 | "每单最少能买几件？比它少一件、多一件分别是几件？" |
| 2 | 模型追问 | 大模型（现场写） | 答错 / 部分对第 1 次 | "你说对了 1 这个边界点。不过 50 属于中间值……" |
| 3 | 预写提示 L0（只指方向） | 老师 | 卡住 / 要答案第 1 次；模型失败时兜底 | "想想边界本身、边界外面、边界里面，各取一个值。" |
| 4 | 预写提示 L1（更具体，不说答案） | 老师 | 设计上是 L0 之后的下一级（见第七节问题 2） | "最少能买 1 件，那和 1 紧挨着的两个数是多少？" |
| 5 | 讲解原文 | 老师的参考答案 | 答错 2 次、卡住 / 要答案 2 次、答非所问 2 次 | "取 0、1、2。0 刚越过下边界，系统应拒绝……" |

**分法的两条原则**：

1. **按学生的情况分**：答错 / 部分对说明学生在想，由模型针对他这句话追问；卡住 / 要答案是最容易泄露答案的场景，不让模型发挥，只给老师写好的提示；答非所问就换个简单问法把他拉回来。
2. **越关键的内容越不交给模型**：模型只写追问，而且不能说出还没答到的要点；方向性提示由老师写；最后的讲解一定是老师的原话。

## 七、目前的局限

| # | 问题 | 现状 | 建议 |
|---|---|---|---|
| 1 | 第 1 层判断准不准还没测 | 比如"哈哈，0 吧"算无关还是部分对，要靠模型理解 | 用 5 种模拟学生评测，目标 type 一致率 ≥ 85% |
| 2 | **L1 提示显示不出来** | 卡住 / 要答案第 2 次就直接讲解，轮不到 L1；模型失败兜底时按"答错次数"取提示，也只会取到 L0 | 方案 1：卡住 / 要答案改成第 1 次 L0、第 2 次 L1、第 3 次讲解（推荐）；方案 2：预写提示共用一个级别，给过 L0 下一次就给 L1 |
| 3 | 模型失败时按答错处理 | 实测 Gemini 503 时，答对的话题被记成"看了讲解" | 改成不计次、请学生再发一次（需组里决定） |
| 4 | 学生这句在提示词里出现两次 | 先保存消息再拼提示词，"最近对话"里已经有这一句 | 拼"最近对话"时去掉最后一条 |
