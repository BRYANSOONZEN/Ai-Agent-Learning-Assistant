## 1. 改判改的是什么

| 项 | 内容 |
|---|---|
| 改什么 | 一次 AI 对话里，一个话题的结果（`dialogue_topic_state.result`） |
| 能改成什么 | 自己答出 `SELF_CORRECT` / 提示后答出 `HINT_CORRECT` / 讲解后会用 `REVEALED_APPLIED` / 讲解后仍不会 `REVEALED` |
| 能改哪些 | 已结束的对话里，已经有结果的话题，包括"答非所问被跳过"的（可能是 AI 把对的回答判成了答非所问） |
| 不改什么 | 对话原文、每句话的判定（`judged_type`）、答错和卡住次数、练习题和掌握度 |

老师有三个动作：

| 动作 | 说明 | 理由 |
|---|---|---|
| 改判 | 选一个不同的结果 | 必填，不超过 200 字 |
| 确认无误 | 老师看过，AI 判得对。不改变结果，只留下记录 | 不用填 |
| 撤销 | 取消之前的改判或确认，回到 AI 的结果 | 不用填 |

"确认无误"是给评测用的：只有"没改判"分不清是"老师看过觉得对"还是"老师没看过"，算一致率时只算老师看过的。

说明：`result` 严格说不是模型直接给的，是模型判每句话、程序再按规则算出来的。页面上统一叫"AI 的判定"。

## 2. 改判之后，什么跟着变

系统统一用**实际结果**：老师改过就用老师的，没改过就用 AI 的。AI 原来的结果一直保留。

| 地方 | 变化 |
|---|---|
| 概念层（`LayerService`） | 按实际结果算好 / 一般 / 不好 |
| 预警证据 | 显示实际结果，标"老师改判"、理由和 AI 原来的结果 |
| 诊断页的话题结果（`DiagnosisService`） | 显示实际结果 |
| 学生的对话进度和总结（`DialogueService`） | 显示实际结果，不显示理由。已经发出的对话消息不改 |

**预警怎么变。** 只有改判的这次对话是概念层正在用的那次（最近一次已结束的），才重新判断。更早的对话改判只留记录，不影响预警。

重新判断的做法：关掉这个学生 × 知识点的待处理预警（注明"改判后重新判断"），驳回它的待审核建议，再按新的两层状态判断一次，还有问题就生成新的预警和建议。

| 例子 | 改判 | 两层变化 | 结果 |
|---|---|---|---|
| 学生04（B） | 讲解后仍不会 → 提示后答出 | 概念 不好 → 一般；应用 好 | 预警关闭，不再有问题 |
| 学生07（A + B） | 讲解后仍不会 → 提示后答出 | 概念 不好 → 一般；应用 不好 | 预警变成 A，建议换成变式练习 |
| 学生03（A） | 自己答出 → 讲解后仍不会 | 概念 好 → 不好；应用 不好 | 预警变成 A + B |
| 学生05（两层都好，没有预警） | 自己答出 → 讲解后仍不会 | 概念 好 → 不好；应用 好 | 新出现一条 B 预警 |

"确认无误"不改变结果，不会重新判断。老师还没点通过的建议，改动本来就没有保存，重新生成不会丢数据。

**已经开始的干预不自动改。**

| 干预状态 | 改判后 |
|---|---|
| 执行中 | 不动，也不生成新预警；提示老师"这个知识点有执行中的干预，不会自动改变" |
| 已完成 | 前后数据和有效 / 无效不改，那是当时的记录。之后的扫描按实际结果判断 |

## 3. 每一步做什么

### 第 1 步：数据库（`schema.sql`）

| 表 | 加的列 |
|---|---|
| `dialogue_topic_state` | `teacher_result`（改判或确认的结果，空 = 老师没看过）、`teacher_reason`、`teacher_id`、`teacher_at` |
| `alert` | `handled_note`（关闭原因，如"改判后重新判断"） |

- 原来的 `result` 不动，它就是 AI 的结果。
- 不另建历史表：老师第二次改判会覆盖第一次，但 AI 的结果不会丢。评测只需要"AI 的结果 vs 老师最后的结果"。
- 实体 `DialogueTopicState` 加方法 `effectiveResult()`：`teacher_result` 不为空就用它，否则用 `result`。

### 第 2 步：演示数据（`data.sql`）

现在只有学生04 的对话有消息，而且 AI 判得是对的。给学生07 的对话（session 105）补一段消息：学生其实答对了，只是说法不一样，AI 却判错，最后变成讲解后仍不会。这样能真实演示"老师看原文，发现判错了"。

不加学生、不改作答和结果，现有测试的数字不受影响。

### 第 3 步：后端

- `LayerService`、`DiagnosisService`、`DialogueService` 读结果的地方都改用 `effectiveResult()`。
- `TopicEvidence` 加 `topicIdx`、`aiResult`、`regraded`、`reason`。
- 新建 `RegradeService`（在 `intervention` 包）：改判、确认、撤销，以及第 2 节的重新判断。
- `InterventionService` 的 `blocked` 拆成两部分：
  - "有待处理预警或进行中的干预"：继续生效。
  - "上次预警之后没有新数据"：改判时跳过。否则老师改完，新预警会因为没有新作答而出不来。
- 撤销要用 `UpdateWrapper` 把列显式设成空。MyBatis-Plus 的 `updateById` 会跳过空值，话题知识点清不掉就是这个原因。

接口（老师）：

```
GET    /api/teacher/dialogues?courseId=&studentId=&filter=     对话判定列表，一行一个话题
GET    /api/teacher/dialogues/{sessionId}                      一次对话：完整消息 + 每个话题的结果
PUT    /api/teacher/dialogues/{sessionId}/topics/{idx}/regrade 改判或确认：{ result, reason }
DELETE /api/teacher/dialogues/{sessionId}/topics/{idx}/regrade 撤销
```

- `filter`：全部 / 讲解后仍不会 / 老师没看过 / 已改判。
- 改判的返回里说明结果：概念层前后变化，预警是关闭、变化、新建、没变，还是有执行中的干预。
- 只能操作自己课程的对话（`courseService.requireOwned`）。

### 第 4 步：后端测试

用 FakeAiClient，不花钱。

- 第 2 节表格的 4 个例子，各自得到预期的预警变化
- 改判后 AI 的结果还在，实际结果变了；撤销后回到 AI 的结果
- 确认无误不改变预警
- 更早的对话改判，不影响预警
- 有执行中的干预时：干预不变，不生成新预警
- 已完成的干预：前后数据和有效 / 无效不变
- 改判时理由为空、结果不合法、对话没结束：都被拒绝
- 别的老师的课程：被拒绝
- 诊断和学生总结显示实际结果

### 第 5 步：前端

| 页面 | 内容 |
|---|---|
| 新组件「对话记录」抽屉 | 完整对话，按话题分段；每个话题显示结果和三个动作；改判时选结果、写理由 |
| 「干预管理」预警详情 | 概念层每个话题加「查看对话」，打开抽屉；改判过的标"老师改判"，并显示 AI 原来的结果和理由 |
| 「干预管理」新页签「对话判定」 | 列表：学生、话题、知识点、AI 的结果、老师的结果，可筛选；点一行打开抽屉 |
| 改判后 | 一句话提示结果（如"这条预警已关闭"），刷新预警列表和侧边栏数字 |

### 第 6 步：浏览器里走一遍

1. 老师打开学生07 的预警（A + B）→ 查看对话 → 看到学生其实答对了 → 改判为"提示后答出"，写理由 → 预警变成 A，建议换成变式练习。
2. 学生04 的预警（B）→ 改判 → 预警消失，侧边栏数字减 1。
3. 在「对话判定」里筛"老师没看过"→ 确认一条 → 预警不变，这条不再出现在筛选里。
4. 撤销学生07 的改判 → 回到 A + B。
5. 通过一条干预后再改判同一个知识点 → 干预不变，出现提示。
6. 切到学生07：对话总结显示改判后的结果，没有理由。
7. 手机宽度（375 像素）下没有横向溢出。

用浏览器验证时不调 DeepSeek，改判本身也不调 AI。

## 4. 需要你定的一点

**执行中的干预，改判后发现它不该存在，要不要让老师能取消？**

比如已经给学生04 布置了复习，老师才发现 AI 判错了。按现在的计划，学生还得做完。

建议这次不做取消，只提示老师。取消牵涉到学生已经做了一半的任务和推荐表怎么恢复，而且老师是看过证据才点的通过，这种情况不多。如果演示时想展示，可以之后单独加。
