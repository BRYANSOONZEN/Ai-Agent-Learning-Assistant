# 计划：个人学习助手（含干预新方向）

> 状态：**第一版已实现**（第 12 节的第 1、2、5 步，全部用规则和模板，没有调大模型）；**视频处理和课件问答有原型并已用开放视频验证**（第 8.4、8.5 节，还没接进平台）。都还没有 commit。
> 开发记录：`docs/记录-个人学习助手与干预新方向.md`。
> 写于 2026-11-11，整理自组内讨论。文中“待定”的地方需要组内决定后再动手。

---

## 1. 为什么要做

### 1.1 现在的问题

1. **推荐藏在一个页面里。** 学生要主动点进“学习推荐”才能看到推荐和老师布置的任务，不点就不知道。
2. **学完一章没有“总结”。** 学生做完一章，系统已经知道他哪里稳、哪里薄弱、错在哪种误解，但没有一个地方把这些告诉他，也没有告诉他接下来怎么补。
3. **个人干预要老师逐条审核。** 全班几十人、每人十几个知识点，老师审不过来；老师不点，学生就收不到。
4. **全班统计和个人预警是分开的。** 诊断页能看到“某知识点全班 35% 薄弱”，但不会触发任何东西；干预页是一条条个人预警，也不会汇总成全班问题。

### 1.2 要达到的效果

- 学生在任何页面都能点开一个**个人学习助手**，看到**只属于自己的**学习情况和推荐。
- 学完一章后，助手给出**个人定制的总结**：哪里稳了、哪里薄弱、为什么，并可以**通过对话再巩固**。
- 学生可以和助手正常聊天；问到知识时，助手**根据老师的课件和学生的学习情况**回答，但**不给题目答案**。
- 个人问题由系统自动处理，老师只处理**全班层面**的问题。

### 1.3 和必做模块的关系

助手的主要目的是**个人定制化推荐**，属于必做主线里的“荐”（`requirements.md` F-D01、F-D02）的增强，也把“诊”“画”“干”的结果送到学生面前。

它**不算**选做 E1（5E 学习智能体）。E1 是在知识点学习页按 5E 模型引导学习，和助手做推荐、做总结不是一回事。

## 2. 一句话设计

> **规则决定推什么，大模型负责说成针对这个学生的话；学生自己的数据加老师的课件是它的依据；题目答案永远不给它。**

---

## 3. 学生的三种情况

| 情况 | 怎么判断 | 助手做什么 | 这次做不做 |
|---|---|---|---|
| ① 还没有学习数据 | 没有任何完成记录、作答、对话 | 正常聊天：这门课讲什么、从哪开始；问知识按课件回答 | 第二步 |
| ② 一章学到一半 | 这一章有完成的学习项，但没全部完成 | 推荐进度：还有哪些没学、下一步做什么 | 第二步 |
| ③ **学完一章** | 这一章**所有学习项都完成过一次** | **个人定制总结 + 推荐 + 对话巩固** | **先做** |

这次先做 ③。①② 的数据和接口基本是 ③ 的子集，做完 ③ 再补很快。

---

## 4. 什么算“学完一章”

**定义：一章路径里的所有学习项都完成过一次，就算完成。** 完成过一次就一直算完成，之后重做不影响。

系统**已经在记录**每个学习项的完成，不需要新表：

| 学习项类型 | 什么时候记“完成” | 现在的代码 |
|---|---|---|
| 文档 | 打开就算 | `LearnCourse.vue` 打开文档项时调用 `finish` |
| 视频 | 播放到结尾 | `@ended="finish(item)"` |
| 练习 | 交卷 | `@done="finish(item)"` |
| AI 对话 | 对话结束 | `@finished="finish(item)"` |

完成记录存在 `learning_event` 表，`event_type = 'finish_item'`，`target_id` 是学习项 id（`RecordService.logEvent`）。

**判断方法**：取这一章所有未删除的学习项 id，和学生的 `finish_item` 记录对比，全部都有就是学完。

> 注意：只算**已发布**章节里的学习项。老师之后在已发布章节里新加一个学习项，学生就会变回“没学完”，等他完成新项后再算学完。这是否合理，**待定**；另一种做法是“第一次学完时记下来，之后不变”。

## 5. 学完一章后的流程（这次先做）

```
学生完成这一章最后一个学习项
        ↓
系统判断：这一章学完了（第 4 节）
        ↓
助手图标出现提示：“第 2 章完成了，看看你的总结？”
        ↓
学生点开图标
        ↓
个人总结（第 5.1 节）
   ├── 稳了的知识点：一句话带过
   └── 薄弱的知识点：为什么薄弱、错在哪种误解
        ↓
学生选一个薄弱点
   ├── [巩固]  → 针对这个知识点的对话（第 5.2 节）
   └── [做题]  → 推荐的练习（第 5.3 节）
        ↓
做完后，掌握度和对话结果更新，助手的总结跟着变
```

### 5.1 个人总结怎么算

**按这一章的每个知识点**，用和干预相同的两层判断（`LayerService`），不另写一套规则：

| 层 | 来源 | 状态 |
|---|---|---|
| 概念层 | AI 对话里考这个知识点的话题 | 自己答出 = 好；提示后答出 = 一般；讲解后仍不会或跳过 = 差；没做 = 未测 |
| 应用层 | 练习掌握度（`MasteryService`） | 作答不到 3 次 = 未测；≥ 0.6 = 好；否则差 |

再加上**错因**：这个知识点上学生最常选的错项对应的误解说明，出现至少 2 次才算明确（沿用 `InterventionService.MIN_MISCONCEPTION`）。

**规则先算好结论，大模型只负责把结论写成对学生说的话。** 例如交给模型的是：

```json
{
  "chapter": "第 2 章 软件过程模型",
  "points": [
    {"name": "瀑布模型", "concept": "good", "application": "good"},
    {"name": "原型模型", "concept": "good", "application": "bad", "mastery": 0.32,
     "misconception": "把原型模型和增量模型搞混"},
    {"name": "螺旋模型", "concept": "bad", "application": "good"}
  ]
}
```

模型写出：

> 第 2 章你学完了，6 个知识点里 4 个已经稳了。
> 「原型模型」：对话里你讲得清楚，但练习 3 次都和增量模型搞混了。
> 「螺旋模型」：练习做得不错，但对话里还没能自己讲出来。

**不发学生姓名，不发其他学生的数据。** 模型调用失败或检查不过（第 9 节），就用模板拼出同样内容的句子，学生照样能看到总结。

### 5.2 对话巩固：复用现有的 AI 巩固对话引擎

学生点“巩固”时，**不让助手自由发挥，而是复用已有的对话引擎**（`DialogueService` + `DialogueRules`），只把范围缩小到这个薄弱知识点的话题。

| | 助手自己聊 | 复用对话引擎（采用） |
|---|---|---|
| 话题 | 模型临时出 | 老师确认过的话题，只取这个知识点的 |
| 不直接给解 | 难控制 | 已有整套规则：三级提示、泄露检查、变式检验后才给讲解 |
| 判断答没答对 | 模型说了算 | 程序重算要点 |
| 结果有没有记下 | 没有 | 记进对话结果，概念层更新，诊断、画像、干预都跟着变 |

**个人定制体现在两处：**

1. **只练他薄弱的知识点**，不是整章重来。
2. **开场针对他的误解**：开场白由大模型根据错因写，例如“你之前把原型模型和增量模型搞混了，我们先从这里开始”。之后每一轮仍按原有规则走。

需要的改动：对话引擎现在按“章”或“章里某个对话项”开场，要加一种“按知识点开场”（只取关联这个知识点的话题）。

**待定**：巩固对话在**助手面板里**进行（面板要做大），还是**跳到现有的 AI 对话页面**（开发量小很多）。

### 5.3 推荐练习

**挑题仍然用现有推荐规则**（`RecommendService`）：薄弱知识点，最多 5 道，每个知识点最多 3 道，优先“上次做错了”，其次“还没做过”，再次“以前做错过，再巩固一次”。

助手只做两件事：

1. 把推荐**排成顺序**：老师布置的在前，概念层差的先巩固再做题，应用层差的直接做题。
2. 用大模型写一句**针对这个学生的理由**，代替固定的“上次做错了”。

点“去做题”跳到推荐页。**推荐页保留**：它是必做模块的完整展示，也承载“已完成 / 换一道”的反馈。

## 6. 平时聊天

### 6.1 能聊什么

- 正常聊天可以。
- 问到详细知识时，**根据老师的课件和学生的学习情况回答**，并标出出处，例如“出自第 2 章课件”。
- 课件里没有的内容，说明“课件里没有讲到”，不自己编。

### 6.2 “是不是在问答案”的判断

三道防线，前两道不依赖模型：

| 防线 | 做法 | 靠谁 |
|---|---|---|
| ① 模型手里没有答案 | 题目标准答案、错项说明、对话话题的要点和讲解，**一律不交给助手**（第 7 节） | 数据隔离 |
| ② 贴题目检测 | 学生的话和题库题干对比，去掉空格标点后高度相似，就判为问答案，直接拒绝，不调模型 | 程序 |
| ③ 意图判断 | 模型先判断这句话的类型；判为“要答案”时不回答，引导去做题或进巩固对话。沿用对话里已有的 `WANT_ANSWER` 类型 | 模型 |

即使 ③ 判错，因为 ①，模型也拿不出标准答案。

## 7. 数据边界（最重要）

**做法：不让模型自己查数据库。** 后端先整理一份“这个学生能看的资料”，只把这份交给模型。

| 数据 | 给助手吗 | 原因 |
|---|---|---|
| 学生自己的完成记录、作答对错、掌握度、对话结果、画像 | **给** | 个人定制的依据 |
| 学生自己的推荐、老师布置、干预和进展 | **给** | 同上 |
| 已发布的课程框架：章节、知识点、学习项标题 | **给** | 回答“我学到哪”“下一章讲什么” |
| 已发布章节的课件和文档文字 | **给** | 回答知识问题；学生本来就能看 |
| 学生自己选错时看到的误解说明 | **给**（只限他选过的） | 用来写针对性的话；他交卷后本来就看得到 |
| 未发布章节的任何内容 | **不给** | 学生本来就看不到 |
| **题目标准答案** | **不给** | 否则问答案的防线失效。注意：学生交卷后，做错的题本来就会显示正确答案和解析（`LearnQuiz.vue`）；但推荐页会让他重做做错的题，助手如果拿着答案，重做就失去意义。所以一律不给，规则也更简单 |
| **错项说明（他没选过的）** | **不给** | 等于泄露哪个选项是对的 |
| **对话话题的要点、讲解原文、变式题要点** | **不给** | 否则绕过对话“不直接给解” |
| **其他学生的任何数据**，包括全班平均 | **不给** | 隐私；也不说“你比全班低” |
| 学生姓名、账号 | **不发给模型** | 不需要 |

> 关于“学到第一章就只有第一章的记录”：这一点自然成立，记录都是学生自己做出来的，没学的章节没有数据。课程框架和已发布课件则不受学习进度限制。

## 8. 课件处理能力（助手和“一键生成”共用）

### 8.1 现在的问题

老师上传的资料在 `material` 表里**只存了文件**：标题、原文件名、路径、大小、类型，**没有文字内容**。模型读不了 PDF 文件本身，所以助手现在没法根据课件回答。

### 8.2 要加的一步

```
老师上传课件
     ↓
【课件处理】
  1. 抽取文字：PDF、PPT、Word 抽出文字；图片做文字识别；视频取出声音做语音识别（8.3、8.4）
  2. 切段：按页、按标题或按时间切成小段，每段记下属于哪一章、哪个知识点、第几页或几分几秒
  3. 老师校对：识别结果先给老师看，确认后才使用
  4. 存起来：新表，例如 material_chunk（material_id, chapter_id, knowledge_point_id, page, start_sec, text, status）
     ↓                                   ↓
助手：学生提问时，                   一键生成：AI 根据课件起草
把相关内容交给模型                   章节、知识点、题目、话题
```

学生提问时怎么选内容（8.5 节有实测依据）：**一章文字不超过 3000 字就全部交给模型**；更长时才检索最相关的 3 段。

**不同内容怎么取文字：**

| 老师给的内容 | 怎么取出文字 | 状态 |
|---|---|---|
| 章节介绍、文档正文、知识点内容、对话话题 | 本来就是文字，直接用 | 已有 |
| PDF、Word、PPT | 抽出文字，按页和标题切段 | 未做 |
| 图片（照片、截图、扫描件） | 文字识别（OCR）取出图里的字；请老师补一句说明 | 未做 |
| 图表、流程图 | 文字识别只能取出字，看不懂图的意思：先靠老师说明，以后考虑能看图的模型 | 未做 |
| 视频 | 取出声音做语音识别，带时间点（8.4） | **原型已验证** |

### 8.3 老师只上传图片怎么办

1. 先做文字识别（OCR），取出图片里的字，比如幻灯片截图上的标题和要点。
2. 图片里的图表、流程图，文字识别看不懂意思，所以上传时请老师补一句说明，例如“瀑布模型的五个阶段”。
3. 识别结果和老师的说明一起给老师确认。
4. 以后可以考虑能看图的模型，直接理解图意。但这样要把图片发给外部服务，费用也更高，先不做。

### 8.4 视频怎么处理（原型已验证）

原型脚本和完整验证记录：`tools/video_to_text/README.md`。

| 步骤 | 做法 |
|---|---|
| 上传时检查 | 文件 ≤ 200 MB（和后端上传限制一致）；时长 ≤ 60 分钟，更长的请老师分段上传；读不了的文件直接拒绝并说明原因 |
| 取出声音 | 转成 16 kHz 单声道；**没有讲解声音**（只有背景音乐）的视频明确提示老师 |
| 语音转文字 | 本机识别，不把老师的视频发给外部服务。**按课程语言自动选**：中文课用 SenseVoice（快，中文专业词准），英文课用 Whisper（英文更准，可以用章节专业词作提示） |
| 切段 | 30～60 秒一段，带开始时间，回答时能说“视频 01:35”；**每段带上前一段的最后一句（重叠）**，**能对上知识点名称的标上知识点** |
| 老师校对 | 专业词会识别错，必须校对后才使用；在句子上改，改完重新分段、标知识点；同义说法标不上的知识点由老师补 |
| 后台处理 | 中文课（SenseVoice）约 5 倍速，10 分钟的课约 2 分钟；英文课（Whisper）约 1 倍速；放在后台做，页面显示处理状态 |

**为什么限制 60 分钟**：用 Whisper 时，本机 CPU 识别大约和视频一样长（计算机课 10 分钟片段用了 8～12 分钟）；换成 SenseVoice 后约 2 分钟。1 小时的视频要处理约 1 小时，再长老师等不起，也占着服务器。识别只在上传时做一次，学生提问不用等（1.5～4 秒）。有显卡的服务器能快几十倍。

**画面上的文字**（板书、幻灯片）：以后每隔一段时间截一帧做文字识别，第一版只处理声音。

### 8.5 AI 怎么“学”这些内容：检索，不是训练

我们不训练、也不微调模型，而是**检索**：把内容变成带出处的小段文字存起来，学生提问时选出相关内容，和问题一起交给模型，要求它只根据这些内容回答并标出处。

| | 检索（我们的做法） | 训练模型 |
|---|---|---|
| 老师改了课件 | 马上用新的 | 要重新训练 |
| 回答能不能核对 | 每句都有出处 | 查不到依据 |
| 成本 | 只有每次调用的费用 | 要显卡和训练数据 |
| 学生数据 | 不会进入模型 | 有进入模型的风险 |
| 答案泄露 | 答案和话题要点不放进检索库 | 难控制 |

**实测得出的规则**（视频原型，真实模型）：

- 关键词检索**对不上同义词**：问“怎么预防”，视频里说的是“降低……发生率”，那一段怎么也检索不到。所以一章文字不长时直接全部交给模型。全部给的情况下，4 个问题都答对、时间点都对。
- 内容很长时才检索，并给常见词降低分量；**检索前先让模型把问题改写成视频所用语言的关键词**（含同义说法）。计算机课实测：中文问英文课，不改写一段都检索不到，改写后全部答对。
- 问题提到某个知识点时，标了这个知识点的段加分。实测：英文问“彩色日志”，不加分时选中的三段都不对，加分后三段全中。
- 内容再多以后，可以换成能理解意思的向量检索。
- 模型的“思考”也算在输出长度里，上限要给够（4096），否则会返回空回答。

### 8.6 一键起草：章节、知识点、题目、对话话题（未做，已定方向）

**目的**：老师上传视频或课件后，点一下，AI 起草这一章的全部内容；老师只需要看、改、确认，不用从头写。

**组内已定**：AI 只起草，**老师保留确认的权利**。所有起草内容都是草稿，学生看不到；老师逐项确认、修改或删除，发布后才生效。这和平台里已有的“AI 起草对话话题，老师确认后保存”是同一个原则。

**现在有什么、缺什么：**

| 能力 | 状态 |
|---|---|
| 视频转文字、分段、标知识点 | 原型已验证（8.4 节） |
| 根据视频内容回答问题 | 原型已验证（8.5 节） |
| AI 起草对话话题（输入是老师写的问题和答案） | **平台里已有**（`TopicDraftService`） |
| 根据视频、课件一键起草章节、知识点、题目、话题 | 未做 |
| 老师确认页：逐项看、改、删、发布 | 未做 |

**流程：**

```
视频 / 课件 → 转文字、分段（已有）→ 老师校对文字
     → 大模型起草：章节介绍、知识点、选择题、对话话题（每项标出处，如“视频 03:20”）
     → 程序检查（不合格的标红，说明原因）
     → 老师确认页：逐项通过 / 修改 / 删除
     → 发布（已有）
```

**起草什么、程序检查什么：**

| 起草内容 | 包括 | 程序检查 |
|---|---|---|
| 章节 | 标题、学习目标、简介 | 不能为空 |
| 知识点 | 名称、一两句说明、出处 | 不能和已有的重复；出处那段里要真的讲到 |
| 选择题 | 题干、4 个选项、答案、解析、每个错误选项对应的误解说明、关联的知识点、出处 | 答案必须是其中一个选项；只有一个正确答案；题干不能直接写出答案；必须关联到这一章的某个知识点；不能和已有的题重复 |
| 对话话题 | 情境问题、参考答案、要点、三级提示、变式题 | 复用 `TopicDraftService` 现有的格式检查 |

**每一项都标出处**：老师确认时可以点出处，直接跳到视频那几秒或课件那一页核对。

**风险：**

- **答案可能错**：答案一错，学生会被误判，诊断、推荐、干预全部跟着错。所以老师确认不能省，界面上把“答案”和“出处”放在最显眼的地方。
- **识别错字会带进题目**：所以先请老师校对文字，再起草。
- **讲得少的内容出不了好题**：比如只讲课程安排的视频，不起草题目，只提示老师“这段没有足够的知识内容”。

**数据怎么存**：起草内容先存在草稿里（例如加一张 `draft_item` 表，或在已有表上加“草稿”状态），老师确认后才写进正式的章节、知识点、题目、话题表。这样学生端完全不会读到草稿。具体选哪种，做的时候再定。

**怎么验证**（先做原型，再接进平台）：

1. 用技术内容的视频片段，一键起草：MIT 调试课，再从操作系统课里截一段讲技术的 10 分钟。
2. 逐题对照原文核对，统计：能直接用、要改、答案错了、和内容无关，各有几道。
3. 用这些数字决定：能不能接进平台，提示词要怎么改，老师确认页要突出什么。

## 9. 大模型调用汇总

做完后，系统里调用大模型的地方：

| # | 场景 | 状态 | 模型拿到什么 | 程序检查 | 失败时 |
|---|---|---|---|---|---|
| 1 | 老师建话题时起草 | 已有 | 老师写的问题和答案 | JSON 格式、必填项 | 报错让老师重试 |
| 2 | 学生 AI 巩固对话 | 已有 | 话题和要点、最近对话 | 重算要点、长度、泄露检查 | 用预写提示 |
| 3 | **助手：学完一章的总结** | 新 | 这一章的两层结论和错因 | 长度 | 用模板 |
| 4 | **助手：推荐理由和顺序** | 新 | 推荐结果（已由规则挑好） | 长度；不能出现推荐列表以外的题 | 用固定理由 |
| 5 | **助手：平时聊天、问知识** | 新 | 相关课件段落、学习档案 | 先过第 6.2 节防线；长度 | 提示“暂时无法回答” |
| 6 | **助手：巩固对话的开场白** | 新 | 知识点名和错因 | 长度、泄露检查 | 用话题原有问题开场 |
| 7 | **干预：给学生的个性化的话** | 新（第 11 节） | 知识点名、问题类型、错因 | 长度 | 用模板 |

所有新调用都和现有做法一致：

- 通过 `AiCallLogService` 调用，每次记日志（耗时、token、费用、检查是否通过）。
- 不发姓名。
- 测试用 `FakeAiClient`。

**费用控制**：

- 每个学生每天聊天次数设上限，**待定**，建议 20 次。
- 总结只在“学完一章”或数据变化后重新生成一次并存下来，平时打开面板直接显示存好的，不重复调用。

## 10. 界面

### 10.1 图标

- 常驻在页面上，**点开才出来**，不自动弹出。位置先放右下角，之后再调。
- 有新内容（学完一章、老师布置、干预、进展）时，图标上显示一个数字，看过就消失。

### 10.2 什么时候隐藏

- **正在做练习**（交卷前）：隐藏，防止拿它当作弊工具。
- **正在 AI 对话**：隐藏，不和对话抢角色。
- 交卷后看结果时可以出现，例如提示“这次错的两道是同一个误解”。

### 10.3 面板内容（学完一章时）

## 11. 干预新方向（和助手一起做）

### 11.1 改什么

| | 现在 | 新方向 |
|---|---|---|
| 判断、分类（A / B / A+B）、挑题、判断是否有效 | 程序规则 | **不变** |
| 个人干预推给学生 | 老师逐条审核通过才推 | **系统自动推** |
| 给学生的话 | 程序模板 | **大模型按错因写**，失败退回模板 |
| 学生在哪看到 | 推荐页“老师布置”区 | 推荐页 **+ 助手面板** |
| 老师对个人干预 | 事前审批 | **事后可查，可撤回** |
| 全班情况 | 诊断页只显示统计 | 某知识点全班薄弱比例超过阈值，**生成全班预警给老师** |
| 干预管理页 | 一条条个人预警 | 上：**全班预警，按章节分组**；下：个人干预记录（只看、可撤回） |

### 11.2 全班预警

直接复用诊断页已经算好的全班统计（`DiagnosisService.course` 返回的 `ClassPoint`：练过人数、薄弱人数、最常见误解）：

- 练过人数 ≥ **最少人数**（待定，建议 5）
- 薄弱人数 / 练过人数 > **阈值**（待定，建议 30%）

满足就生成一条全班预警，附最常见错因，例如：

> 「螺旋模型」全班 35% 薄弱（14 / 40），最常见错因：把螺旋模型的风险分析和原型模型混在一起（9 人）。建议课上重讲。

### 11.3 待定

- **A+B 要不要也自动？** 两层都差的问题较重，建议仍交老师审核，只让 A 和 B 自动。
- 改扫描代码时，顺手修掉**重复预警**问题：现在打开干预管理页时，`board()` 和 `openCount()` 两个请求同时扫描，会把同一条预警建两次。

## 12. 分步实现顺序

按我们一步一步来的习惯，每一步做完、测试通过、你确认后再做下一步。

| 步 | 内容 | 调用模型 | 依赖 |
|---|---|---|---|
| 1 | **章节完成判断** + 学完一章的**两层总结**接口（规则 + 模板，先不调模型） | 否 | 无 |
| 2 | **前端图标和面板**：显示总结、推荐、老师布置；做练习和对话时隐藏 | 否 | 1 |
| 3 | 总结和推荐理由改由**大模型写**，失败退回模板 | 是 | 1、2 |
| 4 | **按知识点开场的巩固对话**（复用对话引擎）+ 针对误解的开场白 | 是 | 1 |
| 5 | **干预新方向**：个人自动、全班预警、撤回；修重复预警 | 是（个性化的话） | 无 |
| 6 | **课件处理能力**：抽取文字、切段、存表 | 否 | 无 |
| 7 | **平时聊天**：三道防线 + 按课件回答 | 是 | 6 |
| 8 | 情况 ①②：没有数据、学到一半 | 视情况 | 1、2 |

做完第 1、2 步，就能演示一个完整的“学完一章 → 助手给出个人总结和推荐”，而且不用调模型。

## 13. 测试要点

全部用 `FakeAiClient`，不调真实模型。

| 测什么 | 用例 |
|---|---|
| 学完一章 | 全部完成 = 学完；少一项 = 没学完；未发布章节的学习项不算；重复完成不重复计 |
| 两层总结 | 好 / 一般 / 差 / 未测各组合；错因出现 1 次不算、2 次算 |
| 数据边界 | 交给模型的内容里**不包含**标准答案、话题要点、其他学生数据、姓名（直接检查拼好的提示词） |
| 贴题目检测 | 原样贴题干 → 拒绝；改几个字 → 仍拒绝；正常提问 → 放行 |
| 模型失败 | 超时、返回空、超长、格式错 → 都退回模板，学生照样看到内容 |
| 推荐理由 | 模型提到推荐列表以外的题 → 不用它的理由 |
| 巩固对话 | 只出现这个知识点的话题；仍遵守不直接给解 |
| 全班预警 | 刚好等于阈值不报、超过才报；练过人数不足不报 |
| 干预自动执行 | 自动推送；老师撤回后学生那边消失；A+B 按决定处理 |
| 重复预警 | 两个扫描同时执行，只建一条 |
