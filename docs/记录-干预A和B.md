## 第 0 步：读现有代码（2026-11-03）

**结果：完成，发现一个影响计划的问题。**

- 后端还没有登录，"当前学生"在代码里固定为 5 号（学生01），"当前老师"固定为 2 号（李老师），一共 7 个文件直接用到。
- 影响：计划第 7 步要在浏览器里切换成学生03、04、07 去做题，但后端不管前端登录成谁，都当成学生01，所以没法走。
- 现有 42 个测试也是按学生01 的种子数据写的（掌握度 0.3704、推荐题顺序等），不能为了演示去改学生01 的数据。

**决定：加一个临时的"演示身份"开关，不碰登录。**

- 后端新增 `DemoIdentity`：请求头里带 `X-Demo-Student-Id` 时就用这个学生，不带时仍是 5 号。原来写死 5 号的地方都改成问它。
- 前端：浏览器里存了 `se-demo-student-id` 时，请求自动带上这个头。
- 学生01 的数据不动，现有测试不受影响。
- 这只是开发和演示用的过渡办法，后端登录做好后，换成"从登录信息里取当前用户"，删掉这个开关。
- 同样因为没有登录，计划里"学生调用老师接口被拒绝"这一条现在测不了，放到登录做好之后。

**做法和结果：成功。**

- 新增 `common/DemoIdentity.java`；`RecordService.currentStudentId()` 和 `DialogueService` 建对话时改用它；删掉 `DialogueService.DEMO_STUDENT_ID`。
- 前端 `api/request.js`：登录角色是学生、且浏览器存了 `se-demo-student-id` 时，请求带上 `X-Demo-Student-Id`。
- 小失败：第一次写正则时 `\d` 在命令行里被转义，编译报 "illegal escape character"；改成 `[0-9]{1,9}` 后通过。

## 第 3、4 步：后端判断、审核、执行、看效果（2026-11-03）

**结果：成功，编译一次通过。**

新包 `intervention/`：

| 文件 | 作用 |
|---|---|
| `entity/Alert.java`、`entity/Intervention.java` + 两个 Mapper | 对应两张新表 |
| `dto/InterventionDtos.java` | 证据快照（Evidence）、老师总览（Board）、预警、干预、学生的"老师布置" |
| `service/LayerService.java` | 两层状态：概念层看最近一次已结束对话里该知识点的话题（答非所问跳过的不算），应用层看掌握度（不到 3 次为未测）；`classify` 组合成 A / B / AB |
| `service/InterventionService.java` | 扫描、建议、审核、执行、看效果、学生视图 |
| `controller/InterventionController.java` | 4 个接口，见下 |

接口（和计划相比做了合并，老师页一次取全）：

```
GET  /api/interventions/board?courseId=1   扫描 + 待处理预警（带系统建议）+ 干预列表 + 统计
POST /api/interventions/{id}/review        通过（可改题目、留言）/ 驳回
PUT  /api/alerts/{id}  {status: ignored}   忽略预警（它的建议一起驳回）
GET  /api/interventions/mine               学生：执行中的和最近 7 天完成的
```

实现时定下的细节（计划里没写死的）：
- **驳回 = 这次不干预**：建议驳回后预警也标为忽略，不会留一条"待处理但没有建议"的预警。
- **不重复报警**：已有待处理预警或待审核 / 执行中的干预时不报；上一条预警之后没有新作答、新对话时也不报（老师忽略后不会马上又冒出来）。
- **干预无效后再报**：这次不做 D，但如果上一次干预无效、学生之后的数据仍满足条件，会重新生成预警，并在说明后面加"上一次干预后仍未解决"。
- **B 的"看过课件"**：用 `view_item` 或 `finish_item` 都算。学习页已经学完的内容不会再记 `finish_item`，只认 `finish_item` 的话 B 可能永远完成不了。
- **练习布置**：写进推荐表（source = teacher），学生用原来的推荐做题接口做；系统推荐跳过老师布置的题，不占 5 道名额。干预结束时，没做对的题还给系统推荐。
- **老师改题**：只能布置这个知识点下的题，至少一道。

`RecommendService`：系统推荐跳过 source = teacher 的题；新插入的推荐写 source = system。

**结果：三条线都走通了。中途发现 5 个问题，已修 4 个，1 个记录在案。**

走的过程（老师：李老师；学生用演示开关切换）：

6. 375 像素宽（手机）下干预管理页没有横向溢出；话题管理里两个话题显示"考：边界测试值的选取 / 边界错误的成因"，编辑时知识点已选好。
