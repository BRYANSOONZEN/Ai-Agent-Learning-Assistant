# 设计方案：学习资料 → 费曼式 AI 对话 → 练习

> 状态：**讨论稿，还没有改代码**（模块一的“完成判定 + 按顺序解锁”除外，已实现）。
> 来源：老师板书指出“AI 对话的起点和目的不清楚、怎么量化”，组里 2026-11-24 讨论后定下这份方案。
> 每一项都标了状态：**已定** = 组里已经决定；**建议** = 我提的，等组里确认；**已实现** = 代码里已经有。

---

## 〇、一句话

学生看完资料常常“以为自己懂了”。我们在资料和练习之间加一段**费曼式对话**：学生把知识点讲给 AI 扮演的同学听，讲不清楚的地方就是真正没懂的地方，可以当场回看资料补上，再去做练习。**对话不打分，掌握情况由练习决定。**

## 一、整体流程

```
模块一：学习资料                       模块二：检测掌握情况
┌──────────────────────┐            ┌──────────────────────────────────────────┐
│ 视频 / 文档            │            │（可选）费曼式 AI 对话  →   练习（单元测试）  │
│ 学完才解锁下一项        │   ───→    │  讲清道理、找出缺口         会不会用、打分     │
│ 资料处理：转文字 + 定位  │            │  不打分，输出诊断           分数决定掌握情况   │
└──────────────────────┘            └──────────────────────────────────────────┘
                                                       │
                                                       ↓
                                          学习助手：练习不好的知识点 → 补救
```

| 项目 | 决定 | 状态 |
|---|---|---|
| 对话的位置 | 一定在练习**之前** | 已定 |
| 对话打不打分 | **不打分**，只做诊断 | 已定 |
| 掌握情况看什么 | 只看练习 | 已定 |
| 对话用什么方法 | 费曼学习法：学生讲给 AI 听 | 已定 |
| 老师要不要加对话 | 老师自己选；加的话一定排在练习前面 | 已定 |
| 练习之后的补救 | 归学习助手，不另做“错因追问”对话 | 已定 |

## 二、为什么这样设计（答辩用）

| 问题 | 理由 |
|---|---|
| 为什么要有这一步 | 看完资料容易产生“理解的错觉”：觉得懂了，真要讲却讲不出。直接做题的话，错了不知道哪里没懂，选择题还可能蒙对 |
| 为什么用“讲出来” | 自我解释效应：用自己的话解释比反复看资料学得更好；讲不下去的地方就是缺口，学生自己就能发现 |
| 为什么 AI 当“不懂的同学” | 面对同学比面对老师更敢讲；同学问“为什么”很自然，不像被考 |
| 为什么放在练习之前 | 刚学完印象最新，最容易暴露“以为懂了”的地方；先把道理理清再去用 |
| 为什么不打分 | 对话的目的是暴露问题。要打分，学生会怕说错、不敢暴露；而且有追问和引导，每个人走的路不一样，分数不公平 |
| 和老师板书的不同 | 板书是“单元测试 → 对话 → 对话分值”。我们把对话移到练习前、不打分：放在练习后会和学习助手的补救重叠；对话拿来打分既不准也违背它的目的 |

> 引用的研究（理解的错觉 Rozenblit & Keil 2002；自我解释效应 Chi 等）写进答辩材料前要再核对原文。

## 三、模块一：学习资料

### 3.1 完成判定和按顺序解锁（已实现）

- 视频：真正看过的时长 ÷ 总时长 ≥ 90%。
- 文档：读满 30 秒，并点“我已读完”。
- 上一项学完，下一项才解锁。

公式和规则见 [学情计算方法与公式.md](学情计算方法与公式.md) 第一节。

### 3.2 资料处理：让大模型读懂这一章（建议，未实现）

老师上传资料后，后台自动处理，得到带位置的文字（“资料索引”）：

| 资料 | 处理 | 位置 |
|---|---|---|
| 视频 | 转成文字（原型在 `tools/video_to_text/`，还没接入平台） | 每句带时间点，如 03:15 |
| PDF | 取出文字 | 页码 |
| 页面上的文字 | 按段落分开 | 第几段 |

资料索引会被用到三个地方：
1. AI 识别本章知识点；
2. 对话里学生讲不出来时，指出“回看视频 03:15～04:30”；
3. 学习助手补救时，指出回看哪一段。

**没接入视频转文字之前**：只能指到整个视频，或者由老师手动给知识点标时间段。

## 四、知识点蓝图：整条链的锚

### 4.1 蓝图是什么（建议）

每个知识点一份，老师确认后就是**唯一的标准**，资料、对话、练习都挂在它上面：

| 内容 | 例子 |
|---|---|
| 知识点 | 边界测试值的选取 |
| 要点（3～4 条） | ① 边界外的值　② 边界上的值　③ 边界内侧的值　④ 错误常发生在边界附近 |
| 常见误解 | 只测边界本身；测中间值最有代表性 |
| 资料出处 | 视频 03:15～04:30；文档第 2 段 |

### 4.2 老师的三个入口，汇到同一份蓝图（建议）

```
入口 1：只有资料          入口 2：资料 + 老师自己的题目        入口 3：全部手写
AI 从资料识别知识点        老师的题原样保留；AI 反推：           老师手动填
                          每题考哪个知识点、
                          每个错误选项对应什么误解
        └──────────────────────┬──────────────────────────────┘
                               ↓
                  知识点蓝图（老师确认、修改）
```

- 老师**可选**写一两句本章学习目标（可以直接用章节介绍）。AI 对照着把知识点标成“重点”或“可选”。
- 老师目标里有、资料里找不到的，提醒老师补资料。

### 4.3 保证整条链连续（建议）

发布前给老师看一张对照表：

| 知识点 | 资料里讲了吗 | 对话 | 练习 | 状态 |
|---|---|---|---|---|
| 边界测试值的选取 | 视频 03:15、文档第 2 段 | 有 | 3 题 | 完整 |
| 边界错误的成因 | 视频 05:40 | 有 | 1 题 | 题目偏少 |
| 等价类划分 | 没找到 | 有 | 2 题 | 资料缺失 |

- 缺哪一格就提示老师去补，不强制拦着发布。
- 老师改了知识点，挂在上面的对话和题目自动标成“需要更新”。

## 五、对话和练习的关系

### 5.1 按知识点连，情境不同（建议）

**同一个知识点：对话问“为什么”，练习考“会不会用”，情境、数字、问法都不一样。**

```
知识点：边界测试值的选取
 ├─→ 对话：同学要测商城“每单 1～99 件”，请学生讲测下限挑哪些值、为什么
 └─→ 练习：“年龄 18～60 岁，测下限应选哪组值？”
          正确：17、18、19        → 要点 ①②③
          错误 A：只测 18         → 误解“只测边界本身”
          错误 C：测 30           → 误解“测中间值最有代表性”
```

练习的每个错误选项都对应一个误解或一条要点，学习助手就能把两边连起来看：

| 对话 | 练习 | 说明 | 补救 |
|---|---|---|---|
| 没讲清要点 ① | 选了“只测 18” | 同一个缺口，概念没懂 | 先复习 |
| 讲清了 ① | 还是选错 | 会讲不会用 | 多做变式题 |
| 没讲清 ① | 选对了 | 可能蒙对 | 提醒再确认 |

### 5.2 保证对话不泄题（建议）

| 关 | 做法 |
|---|---|
| 起草时避开 | **先有题目，再起草对话**；把同一知识点的题目交给 AI，要求场景不能用同样的情境对象、数字和问法 |
| 程序检查 | 比较情境对象、数字、文字相似度；再让 AI 判断“讲完这个场景能不能直接照搬到这道题” |
| 老师确认 | 对话场景和练习题并排显示，有问题的地方标出来 |

## 六、费曼式对话本身

> 引导、结束和有效性的细化设计（参考了 Khanmigo、AutoTutor、Betty's Brain、LearnLM）见 [设计方案-AI对话的引导、结束与有效性.md](设计方案-AI对话的引导、结束与有效性.md)。

### 6.1 场景

| 项目 | 内容 | 状态 |
|---|---|---|
| 学生的角色 | 小老师，把知识讲给别人听 | 已定 |
| AI 的角色 | 一个还没学过这章的同学：好奇、会追问、偶尔有错误想法；不评判、不讲课、不给答案 | 建议 |
| 场景怎么来 | AI 按知识点起草，老师确认（沿用原来“AI 起草 → 老师确认”的流程和底层代码） | 建议 |
| 场景不重复 | 起草时告诉 AI 这门课已经用过的场景，要求换类型、换情境对象；老师可以一键换 | 建议 |
| 场景类型库 | 同学请教 / 新人求助 / 帮忙检查（故意带错）/ 生活类比 / 二选一争论 | 建议，待定 |
| 每个学生换细节 | 骨架由老师确认，每个学生开始时只换数字和对象，防止互抄 | 建议，待定 |

### 6.2 一个知识点的结构（固定）

```
① 开场：AI 带着一个具体问题来请教
② 学生讲解
③ AI 追问（最多 3 次），一次只问一个
④ AI 复述：“我理解的是……对吗？”（故意保留学生没讲到的漏洞）
⑤ 学生确认或纠正
⑥ 小结：讲清楚的、还没讲到的、可能有误解的
```

结构固定，是为了保证每次都在检查理解；变的是场景。

### 6.3 每一轮怎么决定下一步

**模型判断，程序决定。**

模型每轮输出：
- 这句话是哪一类：讲解、提问、卡住、闲聊、要结束；
- 每条要点的状态：讲清楚 / 讲到但不完整 / 没讲到 / 讲错了；判“讲清楚”或“讲错了”时必须**引用学生原话**，程序核对原话确实存在；
- 发现的误解。

程序按优先级选下一步：

| 优先级 | 情况 | AI 怎么回 |
|---|---|---|
| 1 | 学生提问 | 根据资料简短回答并标出处，再请学生接着讲 |
| 2 | 学生卡住 | 先给讲解框架（“先说挑哪几个值，再说为什么”）；还卡住就指资料出处。**不给答案** |
| 3 | 有要点讲错了 | 用常见误解装傻追问 |
| 4 | 有要点没讲到 | 针对其中一条问“为什么 / 那如果……”，不说出要点本身 |
| 5 | 都讲到了，没举过例子 | 请学生换个例子讲 |
| 6 | 追问满 3 次，或全部讲清楚 | 复述 → 小结 |
| — | 闲聊 | 接一句，拉回话题；连续 3 次直接小结 |

### 6.4 次数（为了控制节奏和费用，不为打分）

| 项目 | 建议值 |
|---|---|
| AI 每个知识点最多追问 | 3 次 |
| 学生每个知识点最多说 | 15 句，到了就小结 |
| 连续闲聊 | 3 次就小结 |

### 6.5 什么时候算完成（练习才解锁）

$$
\text{对话完成} \iff \text{每个知识点都认真讲过至少一次} \ \land\ \text{学生点了“我准备好了，去做练习”}
$$

不要求讲对、讲全。讲不全的地方写在小结里，学生带着它去做练习。

### 6.6 例子

| 轮 | 谁 | 内容 | 要点 |
|---|---|---|---|
| 1 | AI | “我要测一个商城，每单只能买 1～99 件，该测哪些数量呀？” | |
| 2 | 学生 | “测 1 和 99，它们是边界。” | ② 讲清楚 |
| 3 | AI | “测 1 就够了吗？有人下单 0 件会怎样？” | 引导 ① |
| 4 | 学生 | “0 也要测，应该被拒绝。” | ① 讲清楚 |
| 5 | AI | “那比 1 大一点的 2 呢？” | 引导 ③ |
| 6 | 学生 | “里面的话测 50 就行，中间有代表性。” | 出现误解 |
| 7 | AI | “可是程序员把 ≥1 写成 >1 的话，测 50 能发现吗？” | 用误解追问 |
| 8 | 学生 | “发现不了，所以要测 2，错误一般在边界附近。” | ③④ 讲清楚 |
| 9 | AI | “我理解一下：测下限要测 0、1、2，因为错误常出在边界附近，对吗？” | 复述 |
| 10 | 学生 | “对！” | |
| 11 | 小结 | 讲清楚了全部要点；一开始认为中间值有代表性，后来自己想明白了 | |

AI 一次都没给答案，四条要点都是学生自己说出来的。

## 八、起草和一键生成

```
资料 → 资料处理（模块一）→ AI 生成知识点蓝图 → 老师确认
     → 练习题（老师的题，或 AI 出题）→ 老师确认
     → 对话场景（避开练习题的情境）→ 老师确认 → 发布
```

- **先蓝图，再题目，再对话**：蓝图对了后面才对；先有题目，对话才能避开它。
- 手写和一键生成走同一套数据，只是起草人不同。
- 一键生成估计 4～5 天（视频转文字接入约 1.5 天、PDF 取文字约 0.5 天、生成和审核页面约 2～3 天）。

## 十二、定下来的对话规则（2026-11-24，组里讨论后定）

用第 6 章第 3 个知识点“智能测试的概念与三大特性”做过一次真实草稿（`tools/feynman/验证结果/知识点3-草稿-第1次/`：16 秒、约 0.03 元，程序检查 4/4 通过）。

| 规则 | 定的值 | 理由 |
|---|---|---|
| 每次对话最多几个知识点 | **2 个**，老师勾选（系统可以建议“重点”的） | 每个知识点 5～8 分钟；2 个约 10～15 分钟，再多学生会疲劳、敷衍 |
| 对话的位置和锁 | 一定在练习前面；对话完成后练习才解锁（沿用第一大模块的按顺序解锁） | 先讲清道理再去用 |
| 草稿内容 | 场景、小林开场白、带着的误解、每条要点的判断标准（讲清 / 不完整）和三级提示、指向的资料、考一考小林（教对 / 漏教时小林的回答）、复述要点 | 老师审核、可改、可试聊 |
| 三级提示 | L1 泛泛追问 → L2 情境追问 → L3 聚焦提问 → 指出资料位置；**每条要点各算各的**；学生没有新内容才升级 | 参考 Cognitive Tutor、AutoTutor；避开“连点按钮跳到答案”的问题 |
| 每个知识点最多几次 | **10 次**，满了**自动结束**（不靠学生点按钮） | 保证一定会结束 |
| 谁判断讲清没有 | **大模型**：每轮判断一次；结束时读完整段对话再总评；判“讲清楚”必须引用学生原话，程序核对 | 读懂换了说法的回答；前后合起来算 |
