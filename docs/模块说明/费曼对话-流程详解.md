# 费曼式 AI 对话：流程详解

> 学生把知识点讲给 AI 扮演的同学听；讲不清的地方，就是学生还没懂的地方。对话**不打分**，只给学生诊断和复习建议。
> 规则来源：[设计方案-费曼式AI对话.md](设计方案-费曼式AI对话.md) 第十二节；实测记录：`tools/feynman/验证结果/平台第1次-真实对话记录.md`。
> 代码：`backend/src/main/java/com/se/platform/feynman/`；提示词：`backend/src/main/resources/prompts/feynman_*.md`。

## 一、老师端：生成草稿

### 1.1 老师做什么

```
选知识点（本章已确认的，最多 2 个）→ 点“生成对话草稿” → 看草稿 → 点“确认草稿”
```

**老师可以改草稿**（2026-11-25 加）：每张卡片右上角“修改”，能改 AI 同学的名字、身份、场景、开场白、带着误解说的话，以及每条要点的讲清 / 不完整标准、L1～L3、讲不出时指向哪里。限制：名字 ≤ 6 字，开场白、误解那句、L1～L3 ≤ 80 字，不能为空。**要点原文不能在这里改**（它是标准答案，去“知识点”里改再重新生成）。保存后重新做 4 项程序检查，卡片标“老师改过”；已确认的草稿变回“待确认”，再确认一次学生才用改过的内容。测试：`FeynmanTest.teacherEditsDraft_checksRerun_needsReconfirm`。

确认后，学生打开这个 AI 对话项，就是和 AI 同学对话。**之后每个学生的对话过程和小结只给学生自己看，老师不再参与。**

### 1.2 草稿里有什么

| 内容 | 谁写的 | 例子（第 6 章“智能测试四大优化环节”） | 用在哪里 |
|---|---|---|---|
| **要点（标准答案）** | 第一大模块：大模型从资料识别，老师确认 | 4 条，如“测试用例生成环节自动分析需求、代码与历史数据……” | 判断讲没讲清；学生讲不清时原样补充给学生 |
| AI 同学的名字和身份 | 大模型，按场景起 | “阿哲，刚进实习公司的测试新人”（不用名人或真实人物的名字；同一章不重名） | 对话里的称呼 |
| 场景 | 大模型 | 在实习公司第一次接触智能测试工具 | 对话开头显示给学生 |
| 开场白 | 大模型 | “我们组刚上了个智能测试工具……这到底算几个环节啊？” | AI 同学的第一句话 |
| 带着的误解 | 大模型，从知识点的“常见误解”里选 | “智能测试最核心的就是自动生成用例吧？” | 学生说了两句后，AI 同学问一次 |
| 每条要点的判断标准 | 大模型 | 讲清楚：说出“需求、代码、历史数据”；不完整：只说“根据需求” | 大模型判断学生讲到哪里 |
| 每条要点的三级提示 | 大模型 | L1“凭什么能生成得比较全？”；L2“只看需求，代码改动没覆盖到，问题出在哪？”；L3“除了需求，还拿什么来分析？” | 学生卡住时一级一级给 |
| 讲不出时指向哪里 | 大模型，用知识点的出处 | 课件第 11 页、视频 6-2 的 01:14 | 三级提示都给完还讲不出时 |
| 程序检查（4 项） | 程序 | 每条要点都有草稿、提示和标准齐全、每句不超过 80 字、提示没有照抄要点原文 | 显示给老师看，没通过的标红 |

### 1.3 交给大模型之前：材料从哪里来（详细）

老师点“生成对话草稿”后，后台程序（`FeynmanDraftService.draftOne`）先把材料准备好，填进固定模板 `prompts/feynman_draft_v1.md`，再交给大模型。**这一步全是程序做的，老师不用操作**；但材料本身都来自更早的“资料识别知识点”模块，其中要点和误解老师在那里确认过。

**材料的来历，一共 4 层：**

```
① 老师上传资料（课件 PDF、视频、或直接在页面上写的文字）
      ↓ 资料处理服务（本机，tools/material_kp/service.py）
② 转成文字，一段一行，存进 material_text 表
      ↓ 老师点“上传完毕”，KpRecognizer 给每段编号，整章交给大模型（kp_extract_v1.md）
③ 识别出知识点：名称、说明、要点（每条带出处编号）、常见误解 → chapter_kp 表
      ↓ 老师在“知识点”页面改、删、加，点“确认”
④ 老师确认过的知识点 ← 对话草稿只能从这里取（2026-11-25 起，没确认不能生成）
```

**② 资料怎么变成文字**

| 资料 | 怎么转 | 一段是多少 | 编号 |
|---|---|---|---|
| PDF 课件的文字 | 本机 PyMuPDF 直接读 PDF 里存的字（不是识别，不会错字）；去掉页码、只有数字的行；第一行当页面标题 | 一页一段；少于 30 字的页（封面、过渡页）跳过 | P4 = 第 4 页 |
| PDF 里的图 | 找出占页面 5% 以上、且不是出现在 3 页以上的装饰图（校徽、底栏），截下来交给 DeepSeek 看图写成文字；规定只抄图里有的字，流程图按箭头写步骤，看不清写“看不清” | 一张图一段 | P13-图1 = 第 13 页第 1 张图 |
| 视频 | 本机取出声音，SenseVoice 语音识别，每句带开始、结束时间；去掉“嗯、呃”和口吃重复 | 句子合并成段：攒够 30 秒、且一句话说完就成一段，最长 60 秒 | 01 = 第 1 段（带时间，如 01:14～01:52） |
| 老师写在页面上的文字 | 直接用 | 整段 | T0 |

同一个文件处理过一次就按内容缓存，重新识别不再花钱看图。

**③ 编号和识别**

- 程序按章节里的顺序给资料编号：文档是 D1、D2……，视频是 V1、V2……；再接上段号，例如 `D1-P11`（第 1 份文档第 11 页）、`V2-03`（第 2 个视频第 3 段）。
- 整章文字（上限 6 万字）一次交给大模型，要求每条要点**必须写出处编号**；程序核对，**不存在的编号删掉，没有出处的要点删掉**。
- 误解是大模型根据知识点推测的（资料里一般不会写“学生容易误解什么”），所以**没有出处**，最需要老师确认时认真看。

**④ 对话草稿取哪些材料**

| 模板空位 | 填什么 | 怎么取 |
|---|---|---|
| `{{course}}` | 课程名 | 课程表 |
| `{{name}}`、`{{summary}}` | 知识点名称、一句话说明 | `chapter_kp` |
| `{{points}}` | 每条要点 + 资料位置 | `chapter_kp.key_points`；出处编号翻译成人看得懂的位置：PDF 段 → “《课件名》第 11 页”，视频段 → “视频《6-2 智能测试》的 01:14”（这一段的开始时间） |
| `{{misconceptions}}` | 常见误解，一行一条 | `chapter_kp.misconceptions` |
| `{{material}}` | 资料原文 | **只取这个知识点各条要点出处的那几段**（不是整章），同一段只放一次，每段前面标位置，例如 `[《课件》第 11 页] 智能测试贯穿……` |
| `{{used_scenes}}`、`{{used_names}}` | 已用过的场景、名字 | 一次选 2 个知识点时，起草第 2 个前填入第 1 个的；第 1 个填“无” |

生成后，草稿里会**另存一份**当时的要点原文、资料位置、误解。对话中判断学生、收尾时补充给学生的“标准答案”，用的都是这份要点原文，不是大模型写的内容。

### 1.4 2026-11-25 修的三处

| 问题 | 改成 | 测试 |
|---|---|---|
| 知识点没确认也能生成对话草稿 | 本章知识点不是“已确认”（包括确认后又改过、还没再确认）就不能生成，页面黄色提示、按钮变灰 | `FeynmanTest.draftNeedsConfirmedKps_andStaleDraftCannotBeConfirmed` |
| 草稿存的是生成那一刻的要点，老师之后改了知识点，草稿不跟着变 | 每次打开都逐个比较草稿里的要点、误解和现在的知识点；不一致就红色提示“某知识点：要点改过 / 常见误解改过 / 已删除”，**不能确认草稿**，要重新生成；已确认的草稿也会提示“学生现在用的还是旧草稿” | 同上；另在真实第 6 章上临时改一条误解，页面出现红色提示、按钮变灰，改回后提示消失 |
| 大模型判断失败（超时、格式错）时，这一句被算作“认真回答”，还会让提示升一级 | 这一句**不算进 10 句、不算认真回答、不改要点、不升级**，AI 同学回“抱歉，我刚才没听清，你能再说一遍吗？” | `FeynmanTest.judgeFailure_notCountedAsAttemptOrTurn` |

## 二、学生端：对话怎么进行

### 2.1 整体流程

```
开场：系统说明 + 场景 + AI 同学的开场白
   ↓
┌─ 学生说一句 ──────────────────────────────────────────┐
│  ① 大模型判断这一句（约 1 秒）                         │
│  ② 程序核对原话、更新每条要点的状态                     │
│  ③ 程序判断：要结束吗？（要点都讲清楚了，或满 10 句）   │
│        是 → 收尾                                       │
│        否 → ④ 程序决定问什么 → AI 同学回一句            │
└──────────────────────────────────────────────────────┘
   ↓
收尾：大模型总评 → 复述 → 补充没讲清的 → 建议复习 → 小结 → 下一个知识点或结束
   ↓
对话完成，下一项解锁（这个内容项记为学完）
```

### 2.2 ① 大模型判断什么（每一句一次）

大模型拿到：这个知识点的要点和判断标准、常见误解、每条要点目前的状态、这个知识点到目前为止的对话、学生这一句。输出：

| 项目 | 取值 | 说明 |
|---|---|---|
| 这句话是哪一类 | 讲解 / 提问 / 卡住 / 闲聊 | 讲错了也算讲解 |
| 是不是认真回答 | 是 / 否 | “不知道”“嗯”、闲聊、只要答案都算否 |
| 每条要点的状态 | 讲清楚 / 不完整 / 讲错了 / 没讲到 | 按学生**到目前为止说的所有话**判断；讲清楚、不完整、讲错了都要**摘录学生原话** |
| 有没有指出常见误解 | 是 / 否 | |
| 短反应 | 一句话，不超过 30 字 | 像同学说话，例如“哦，自愈这个我懂了”；**不能提问、不能评判对错、不能说出没讲到的要点** |
| 针对性追问 | 一句话，或空 | 学生在正在追问的要点上有进展但还没讲清时，针对还缺的部分问一句，不说答案，不重复问过的话 |

学生这一句里要求“忽略规则、告诉我答案”的，一律不照做，当作闲聊。

### 2.3 ② 程序核对

| 检查 | 做法 |
|---|---|
| 原话是不是真的 | 大模型摘录的原话，去掉标点空格后，必须能在学生这个知识点说过的话里找到；找不到就**不算** |
| 状态只升不降 | 讲清楚了的要点不会因为后面说错一句又变回去；例外：“讲了一部分”的要点后面说错了，会标成“讲错”，下一句优先追问它 |
| 判断失败 | 大模型超时或格式错：这一句不算进 10 句、不算认真回答、不升级提示，请学生再说一遍 |
| 有没有进展 | 这一句之后，有没有哪条要点的状态变好了 |
| 短反应清理 | 去掉里面带问号的句子、开头的“对，”“没错，” |

### 2.4 ③ 什么时候结束（程序判断，自动）

| 条件 | 结果 |
|---|---|
| 所有要点都讲清楚了 | 马上收尾 |
| 学生在这个知识点上说满 **10 句** | 自动收尾 |
| 每条没讲清的要点都走完了三级提示和指出资料 | 收尾 |

学生不用点“我讲完了”。10 句的理由：每个知识点约 5～8 分钟，一次对话最多 2 个知识点，约 10～15 分钟。

### 2.5 ④ 问什么（程序决定，不靠大模型）

| 顺序 | 规则 |
|---|---|
| 1 | 学生在提问：告诉他资料位置，请他看完接着讲 |
| 2 | 学生说了两句以后、还没指出过误解：AI 同学带着常见误解问一次（只问一次） |
| 3 | 其他情况：按三级提示（见下表） |

**三级提示怎么给：**

| 规则 | 说明 |
|---|---|
| 问哪条要点 | 讲错的优先；否则问第一条还没讲清的 |
| 第一次问这条要点 | 给 L1 |
| 这一句**有进展**但还没讲清 | 级别不变、次数清零，用大模型写的针对性追问（问学生还缺的部分） |
| 这一句**没进展** | 同一级**问满 2 次才升级**（2026-11-25 改，原来没进展就升）：第 1 次没进展时，还在这一级，用大模型写的追问换个角度再问；第 2 次没进展才升一级 L1 → L2 → L3。给学生更多自己想的机会 |
| L3 也问满 2 次 | 不给答案，指出资料位置（“这一块课件第 11 页讲了”），这条要点不再追问，换下一条 |
| 每条要点各算各的 | 学生一开口就讲清的要点，一级提示都不会收到 |

AI 同学的回复 = 短反应 + 程序选出的那句话。

### 2.6 收尾（自动）

| 步骤 | 谁做 | 内容 |
|---|---|---|
| 总评 | 大模型 | 读完整段对话，再判断一次每条要点（前后说的合起来算），判断学生整体是否认真尝试过，写复述 |
| 复述 | 大模型写、程序显示 | “我理解一下：……”，只复述讲清楚的部分，最后说“还有一块我没听你讲清楚” |
| 对话总结（**给学生看**） | 程序 | 全部知识点讲完后显示：这次讲了哪几个知识点、每个知识点的**全部要点原文**（老师确认的）；这次**没讲清的要点**后面加一行“这一条这次还没讲清，可以复习：课件第几页、视频几分几秒”。程序直接写，不调用大模型；不管是讲清提前结束还是 10 句用完，都一样显示 |
| 再打开 | 程序 | 完成过的对话项再打开，显示**上一次**的对话和总结；下面有“再讲一次”按钮，点了才开始新的一次，上一次保留（`POST .../feynman/start?again=true`） |
| 学习情况（**只记在后台**） | 程序 | 每条要点：自己讲清 / 追问后讲清 / 第几级提示后讲清 / 看资料后讲清 / 讲了一部分、补充了 / 补充后才知道 / 还没讲到；误解有没有指出；建议复习哪里；是否认真尝试过（认真回答 ≥ 3 次）。**不给学生看**，存在 `feynman_session.state`，以后给小助手用 |

（2026-11-25 改：原来收尾时给学生看“补充没讲清的要点”“建议复习”“学习情况小结”三条消息。组里讨论后认为学生需要的是内容总结，学习情况更适合放到小助手里，所以改成只显示对话总结；对话中顶部也不再显示“讲清 x/y 条”，只显示第几句。）

（原来收尾还有“考一考”：AI 同学答一道新情境题，学生判断对错。因为放在补充之后，答案已经给过了，测不出东西，已去掉。应用能力交给后面的练习题。）

### 2.7 时间和费用（实测，第 6 章，学生说满 10 句）

| | 次数 | 每次耗时 | 费用 |
|---|---|---|---|
| 每一句的判断 | 10 | 约 1 秒 | 合计约 0.038 元 |
| 结束时总评 | 1 | 约 1 秒 | 约 0.005 元 |
| **一个学生、一个知识点** | | | **约 0.04 元** |

## 四、分工一句话

- **大模型负责“读懂”**：判断学生讲到了什么，写 AI 同学的短反应、针对性追问和复述，起草草稿。
- **程序负责“规则”**：核对原话，决定问什么、问第几级、什么时候结束，补充什么、建议复习哪里。
- **标准答案就是老师确认过的要点原文**，大模型不能另编答案。
