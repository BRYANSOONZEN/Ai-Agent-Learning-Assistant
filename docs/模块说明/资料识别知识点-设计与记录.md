# 资料识别知识点：设计、实现与运行记录

> 用途：最终汇报。所有数字都来自实际运行（2026-11-24，第 6 章「智能测试生成与优化」），原始记录在 `tools/material_kp/验证结果/`。
> 相关设计：[设计方案-费曼式AI对话.md](设计方案-费曼式AI对话.md)（第三、四节：资料处理、知识点蓝图）。

---

## 一、要解决的问题

老师上传的资料（课件 PDF、讲课视频）里有这一章的全部知识，但平台原来读不懂它们：知识点要老师一个个手动录入。
目标：**老师只管上传资料，系统自动整理出本章的知识点草稿，老师改一改、确认就行**；确认后老师和学生都能看到一张“知识点地图”：每个知识点在哪份资料、第几页、视频第几分钟讲到。

## 二、最终设计（组里讨论后定下）

### 2.1 流程

```
老师上传一份视频或 PDF ──→ 马上排队转文字（不等）
        （可以传很多份）
老师点“上传完毕” ──→ 这一章的资料都处理好了，就自动识别知识点
        ↓
提醒老师：大纲上“知识点”入口显示“待确认 8”，页面弹出“识别完成”
        ↓
老师修改（改、删、加）→ 确认 ──→ 同步到知识点表（练习、诊断用）
        ↓
学生在章节介绍里看到知识点地图，点时间直接跳到视频那一分钟
```

### 2.2 关键决定和理由

| 决定 | 理由 |
|---|---|
| 上传后**马上**转文字 | 视频转文字最慢，早开始老师等得少 |
| 老师点“**上传完毕**”才识别 | 识别要看整章资料；老师一份份传，每传一份就识别会跑很多次、结果不完整、多花钱。（讨论过“自动等 2 分钟”，最后改成按钮，老师更清楚） |
| 识别**以章为单位**，测验也以章为单位 | 一个知识点可能分散在几个视频里讲（例如“缺陷自动检测与修复”在 6-2 和 6-4 都讲了） |
| 老师确认后学生才看得到 | AI 草稿可能有错，必须老师把关 |
| 重新识别时**保留老师改过的** | 老师的修改不能白做 |
| 能直接读的就在本机读，读不懂的才交给大模型 | 又快又准又省钱：PDF 文字本机读（不会错字），图片才交给能看图的大模型 |
| 每个知识点、每条要点都要**标出处**，程序核对 | 防止大模型编造；老师点出处就能核对 |

### 2.3 每种资料怎么变成文字

| 资料 | 方法 | 在哪里 | 收费 |
|---|---|---|---|
| PDF 上的文字 | PyMuPDF 直接读 PDF 里存的字 | 本机 | 免费 |
| PDF 里的图（流程图、截图） | 找出有内容的图，交给 DeepSeek 看图写成文字 | DeepSeek | 收费 |
| 视频 | 取出声音，本机语音识别（SenseVoice），每句带时间点 | 本机 | 免费 |
| txt、md、老师写在页面上的文字 | 直接读 | 后端 | 免费 |
| 识别知识点 | 整章文字交给 DeepSeek，每条要点标出处 | DeepSeek | 收费 |

PPT、Word 暂不支持，提示老师转成 PDF 再上传。

## 三、实现

### 3.1 结构

```
前端（Vue）                后端（Spring Boot）                    资料处理服务（Python，常驻）
老师：知识点页 ──────→  上传接口 → 排队（material_job）──────→  service.py
  状态、进度、草稿、           后台线程，一次处理一份                    PDF 文字 + 看图
  修改、确认、地图                                                  视频语音识别（模型只加载一次）
大纲：状态标签            转出的文字 → material_text  ←──────────
学生：知识点地图          上传完毕 → 识别（KpRecognizer → DeepSeek）
                          草稿 → chapter_kp；确认 → knowledge_point
```

为什么 Python 做成**常驻服务**：语音识别模型每次加载要几秒到几十秒；常驻后只加载一次。也因此后端不用装 Python 的库（读 PDF 的 Java 库要下载，组里决定不下载）。

### 3.2 数据表（新增 4 张）

| 表 | 存什么 |
|---|---|
| `material_job` | 每份资料转文字的进度：排队 / 处理中 / 完成 / 失败，失败原因，耗时和 token 统计 |
| `material_text` | 转出来的文字，一段一行：课件一页、一张图、视频 30～60 秒；带页码或开始时间 |
| `chapter_kp_state` | 每章识别走到哪一步：等上传完毕 / 处理资料中 / 识别中 / 待确认 / 已确认 / 失败；用的哪次模型调用 |
| `chapter_kp` | 识别出的知识点：名称、说明、重点或一般、要点（带出处）、常见误解、老师改过没有 |

出处编号：D1-P4 = 第 1 份文档第 4 页；D1-P13-图1 = 第 13 页的图；V2-03 = 第 2 个视频第 3 段。

### 3.3 接口

| 接口 | 谁用 | 作用 |
|---|---|---|
| `POST /api/chapter-items/{id}/file`（原有） | 老师 | 上传后自动排队转文字 |
| `GET /api/chapters/{id}/kp-status` | 老师 | 识别进度、每份资料的状态、知识点草稿 |
| `POST /api/chapters/{id}/kp/upload-done` | 老师 | 上传完毕 |
| `POST /api/chapters/{id}/kp/rerun` | 老师 | 重新识别（保留老师改过的） |
| `POST /api/chapters/{id}/kp/confirm` | 老师 | 确认，同步到知识点表 |
| `POST /api/chapters/{id}/kps`、`PUT/DELETE /api/chapter-kps/{id}` | 老师 | 加、改、删知识点 |
| `GET /api/chapters/{id}/kp-map` | 老师 | 知识点地图（草稿也能看） |
| `GET /api/courses/{id}/kp-badges` | 老师 | 大纲上每章的状态标签 |
| `GET /api/learn/chapters/{id}/kp-map` | 学生 | 知识点地图（只有老师确认过的） |

### 3.4 测试

后端新增 `MaterialKpTest`，4 个测试（用假的处理服务和假的 AI，不联网、不花钱）。后端全部 **120 个测试通过**。

| 测试 | 验证什么 |
|---|---|
| 上传 → 上传完毕 → 识别 | 上传后马上转好文字；没点上传完毕不识别；点了马上识别；模型编出来的出处（D9-P1）被去掉，没有有效出处的知识点被去掉；地图的页码和视频时间正确 |
| 处理失败不卡住 | 视频处理失败时把原因告诉老师；PPT 提示转成 PDF |
| 老师修改、重新识别、确认 | 改过的保留，删掉的、新加的都对；确认后同步到知识点表；学生确认前看不到、确认后看得到；再上传新资料时提示“资料有更新”，学生仍看到上次确认的 |
| AI 回复格式不对 | 重试一次，仍不对就标“失败”并提示重新识别 |

## 四、准确率（每一步都验证过）

| 步骤 | 怎么验证 | 结果 |
|---|---|---|
| PDF 文字 | 抽 5 页（不同版式）和原 PDF 画面逐句对照，共 1362 字 | **错字 0 个**；修了 3 个格式问题（标题和正文粘连、章节号混进正文、“U I”被拆开） |
| PDF 图片 | 第 13 页流程图 + 抽 5 张（示意图、截图），和原图逐条对照 | 流程图 13/13 方框、5/5 条件、箭头全对；6 张里 5 张完全正确，1 张少一个字（箭头压在字上）；**无编造** |
| 视频转文字 | ① 用课件里 30 个专业词检查；② 组员看 6-1 全文 | ① 专业词正确率 83.1%（“测试用例”→“测试用力”17 次、DeepSeek 11 次全错）；② 组员判定基本正确、够用；对照课件估计字准确率约 99% |
| 识别知识点 | 程序核对出处；反向测试；同样输入跑 3 次 | 出处有效率 100%、出处支持率 100%；**反向测试**（出处随机换成无关片段）支持率降到 0～3%，说明检查有效；稳定性 94%～100% |
| 和人工清单对比 | 组员不看模型结果，自己列知识点，算查准率、查全率 | **还没做**（模板：`tools/material_kp/验证结果/第6章-人工知识点（待填）.txt`） |

验证中发现并修好的问题：

| 问题 | 怎么修 |
|---|---|
| 大模型输出被截断（输出上限 8192，加了图片后 3 次截断 3 次） | 上限提高到 16384，截断或格式不对自动重试一次 |
| 看图时模型会猜被遮挡的字 | 提示词要求“照原样抄，看不清写‘看不清’” |
| 稳定性只按名称比太严（57%） | 改成名称相近或出处大部分相同算同一个知识点 |
| 试过按文字位置重新排序 PDF，结果多栏页面左右交错 | 放弃，用 PDF 自带的阅读顺序 |

和第 1 次（7 个）比：第 1 次的“自动化测试的概念与局限”这次拆成了两个；其余一一对应。说明**同样的资料，知识点的粒度会有些浮动**，这正是要老师确认的原因。

**学生端改成圆圈（组里讨论后定）**：表格是给老师核对出处用的，学生不需要看每一页、每一段。学生端改成：
- 一个知识点一个圆圈，**左上角的数字是讲课的先后顺序**，**大圈是重点**；宽度不够时自动换行。
- 一开始圆圈之间画了连线，换行处断开，看起来像“有的知识点有关系、有的没有”，容易误会；改成不画线、只标序号。
- 点圆圈，下面显示一句话说明和两个按钮：“视频《…》· 从 mm:ss 看”（讲得最多的那个视频的开头）、“课件第 x–y 页”。
- 还没解锁的视频、课件，按钮变灰并带锁头，提示“先按顺序学完前面的内容”。
- 老师端保留表格不变。
- 以后可以按练习结果给圆圈上色（掌握 / 薄弱）。

发现并修好的页面问题：知识点地图的表格太宽，把整个面板撑出了页面（出现横向滚动条）→ 改成表格在面板里面横向滚动；视频一格里时间点太多（一个知识点引用了连续 4～9 段）→ 连续的段合成一个时间范围，如“00:30–03:09”。

## 五点五、识别结果的保留（2026-11-24 改）

问题：开发用的数据库原来只在内存里，后端一重启，上传的资料、识别出的知识点全部清空，要重新等约 8 分钟、重新花钱。组里定：**识别过的结果必须完整保留，不能因为重启或服务器出问题让老师重新等。**

| 改动 | 做法 | 效果 |
|---|---|---|
| 数据库存成文件 | H2 从内存模式改成文件模式（`backend/data/platform.mv.db`）；只有第一次启动（没有这个文件）才建表、放演示数据，之后只补建新加的表，不清空（`KeepDataConfig`） | 重启后资料、知识点、学生记录都还在。正式部署用 MySQL，本来就会保留 |
| 资料处理加缓存 | 资料处理服务按文件内容算 SHA-256，处理过的结果存到 `tools/material_kp/.cache/`；同一个文件再来直接用结果 | 即使数据库丢了，重新导入同样的资料只要几秒，不再看图、不再花钱 |
| 崩了接着做 | 后端启动时检查：处理到一半、排队中的资料重新排队；识别到一半的章节重新识别 | 服务器中途出问题，重启后自动接着做，老师不用重新上传 |

单元测试仍然用内存库（每个测试从干净的演示数据开始）。想回到干净的演示数据：停掉后端，删掉 `backend/data` 再启动。

## 六、汇报时可以这样讲

> 老师只要上传课件和视频、点一下“上传完毕”。系统在本机读出 PDF 的文字、把视频转成带时间点的文字；PDF 里的流程图和截图交给能看图的大模型写成文字。然后整章资料一起交给大模型整理出知识点，每条要点都必须标出处，程序逐条核对，编出来的出处会被去掉。
> 我们每一步都量化了准确率：PDF 文字抽查 1362 字零错字；流程图的方框、条件、箭头全部正确；知识点的出处 100% 能在原文找到，并且用反向测试证明这个检查确实能抓出错误。处理一章（39 页课件 + 25 分钟视频）大约 10 分钟、不到 1 元。
> 老师确认后，学生能看到知识点地图，点一下就跳到视频讲这个知识点的那一分钟。
