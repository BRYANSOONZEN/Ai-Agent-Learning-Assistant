## 三、每一项要做什么

### 1. 小问题修补

| 问题 | 改法 | 验收 |
|---|---|---|
| 发布检查只在前端 | 后端发布章节时也检查 3 条（章节介绍、至少 1 项内容、每项完整），不满足返回 400 | 直接调接口发布空章节被拒 |
| 删掉中间的内容后，新加的不一定排在最后 | 新章节、新内容项的顺序号取“最大顺序号 + 1” | 删掉前 2 项再加 1 项，新项排在最后 |

### 2. 老师改判（M10）

详细设计已写好：`docs/计划-老师改判.md`。要点：

- **改什么**：已结束的 AI 对话里，一个话题的结果。能改成 4 种：自己答出、提示后答出、讲解后会用、讲解后仍不会。
- **老师的三个动作**：
  - 改判：必须写理由，不超过 200 字；
  - 确认无误：AI 判得对，留一条记录，评测时用来算一致率；
  - 撤销：回到 AI 原来的结果。
- **存什么**：新表 `topic_review`，存话题进度 id、AI 原来的结果、老师给的结果、动作、理由、老师、时间。**AI 原来的结果一直保留。**
- **改完以后**：系统统一用实际结果（老师改过就用老师的）。概念层、预警证据、诊断页、学生的对话总结都按实际结果显示。如果改的是概念层正在用的那次对话，就重新判断预警。
- **已经开始的干预不自动改**，只提示老师。
- **页面**：老师端新增“对话判定”列表（可以按课程、学生、结果、是否改过筛选），点开看完整对话，在每个话题上改判。

**要先定**：

1. 改判后发现一条执行中的干预不该有，要不要允许老师直接取消？（建议：给一个“取消这条干预”按钮，和撤回同样处理）
2. 计划里还没有“讲解后会用”这个结果，要补上。

**验收**：学生04 从“讲解后仍不会”改成“提示后答出”后，B 预警自动关闭；撤销后恢复原样。

### 3. 简答判定（M5）

- **老师出题**：题型多一种“简答”。填题干、参考答案、**要点**（2～5 条），要点和 AI 对话话题的写法一样；关联知识点。
- **模型判分**：学生交卷后，模型对照要点判断：
  - **对 / 部分对 / 错**；
  - 答到了哪几条要点；
  - 错因属于哪一类（错因的类别由老师在题目上预先写好，模型只能从中选）。
- **拿不准时**：模型给出低把握度，或者输出格式不对时，结果先记为“待老师确认”，**不算进掌握度**，出现在老师的改判列表里（和第 2 项共用同一个页面）。
- **存什么**：
  - `exercise` 加题型 `short_answer`、参考答案、要点、错因类别；
  - `answer_record` 加判定结果、答到的要点、错因、是否待确认；
  - 每次判分调用照常记进 AI 调用日志。
- **进掌握度**：对算 1、部分对算 0.5、错算 0，和单选同一个公式。
- **防泄露**：交卷前不返回参考答案和要点，和单选一样。
- **测试**：继续用 FakeAiClient，不调真实模型。

**要先定**：

1. 错因分哪几类？建议每道题由老师写 2～4 个常见错因，再加一个固定的“其他”。
2. 部分对算 0.5 合不合适？
3. 待确认的题，老师不处理会一直不算分，要不要设一个期限，过期后按模型结果算？

**验收**：老师出一道简答题；学生答对、部分对、答错各一次，掌握度按 1、0.5、0 变化；模型返回格式错误时进入待确认。

### 4. 错因看板（M10）

现在已经有“全班预警”：某个知识点薄弱人数达到练过人数的 30%、而且练过的不少于 5 人时提醒老师，并显示最常见的误解。还要补：

- **按错因汇总**：每个知识点下，每种错因有几个人犯过、各占多少。错因有三个来源：单选的错误选项说明、简答判定的错因、AI 对话里发现的错误想法。
- **提醒规则**：同一错因的人数达到全班 30% 且至少 5 人时提醒，和全班预警用同一套阈值。
- **提醒后能做什么**：只提醒，并给出这个错因相关的题和章节内容，方便老师上课讲。**不做全班干预**（之前已决定不做 C、D）。
- **人数不足 5 人的小班**：不提醒，只显示统计。

**验收**：演示数据里“缺少越过边界的值”这个错因能按人数汇总，达到阈值时出现提醒。

### 5. 评测 T1–T5、P1–P5

| 编号 | 内容 | 规模 | 依赖 |
|---|---|---|---|
| T1 | 学生单条消息 | 20 条 × 3 次；要答案类 16 条 × 10 次 | 无 |
| T2 | 多轮对话脚本 | 3 段 × 4 轮 × 3 次 | 无 |
| T3 | 课件片段 | 约 20 个 | 课件拆分 |
| T4 | 学生简答作答 | 40 条，两人分别标注 | 简答判定 |
| T5 | 模拟学生 | 100 名 × 8 次（高 30、低 30、蒙对 15、粗心 15、无作答 10） | 无 |
| P1 | 提示升级的边界能否守住 | | T1、T2 |
| P2 | 程序状态和模型输出是否一致 | | T2 |
| P3 | 结果稳定性（同一输入多次运行） | | T1 |
| P4 | 课件可见性默认规则会不会泄露答案 | | T3 |
| P5 | 所选模型是否仍然不泄露 | | T1 |

- **做法**：写成独立的评测脚本，**调用真实模型**，不放进单元测试，不进 CI。API key 只从环境变量读取。
- **产出**：每项一份结果表（通过率、泄露次数、费用、耗时）放在 `docs/评测/`，答辩直接引用数字。
- **费用控制**：先算好调用次数和估计费用再跑，总预算不超过立项时定的 100 元。

**要先定**：

1. 要答案类消息的通过标准：一次泄露就算不通过，还是看比例？
2. 换一种说法的泄露怎么判：人工抽查，还是再用模型判一次？
3. “无作答”的学生全程看不到答案，要不要单独统计？

### 6. 课件拆分（M1–M4）

- **范围**：先只支持 **PDF**（用 PDFBox 读文字）。PPT 以后再加。
- **流程**：
  1. 老师上传课件；
  2. 程序按页读出文字；
  3. 模型把每页的内容分成“原理句”和“例题”，并建议关联哪个知识点；
  4. 老师逐条确认、修改或删除，**确认后才生效**。
- **存什么**：新表 `material_segment`，存文件 id、页码、类型（原理句 / 例题）、原文、关联知识点、是否已确认。
- **用在哪**：老师写 AI 对话话题时可以直接引用原理句，自动带上出处（如“课件第 13 页”）；**例题默认不给学生看**，避免泄露答案（对应立项时的发现）。

**要先定**：

1. 拆错了老师怎么改：直接改文字，还是只能删掉重拆？
2. 课件换新版后，已经确认的内容怎么办？（建议：旧的保留，新的重新拆，老师再确认一次）

**验收**：上传演示课件 PDF，拆出原理句和例题，老师确认后能在话题编辑页引用，并显示出处。

### 7. E4 补全（选做）

- **班级难点排行**：诊断页已经有每个知识点的全班薄弱人数，再加一个按薄弱比例排序的列表，重点、难点一起标出来。
- **蒙对型**：练习做对了，但同一个知识点的 AI 对话结果不好（讲解后仍不会）。这其实就是干预里的 B 型，直接复用两层判断。
- **粗心型**：掌握度高（≥ 0.8），但最近在难度低的题上做错过。
- **注意**：这些标记**只给老师看**，页面写清楚是“系统推测”，避免冤枉学生。

**要先定**：作答用时现在没有记录（`time_spent_sec` 为空），要不要开始记，用来辅助判断蒙对？

### 8. E1 补全（选做）：拓展（Elaborate）放到小助手（2026-11-25 提出，待确认）

**现状**：AI 对话改成费曼式后，原来收尾的“考一考”（变式题）已去掉，因为它放在补充答案之后，测不出东西。所以对话里只有 5E 的 4 个阶段，**缺 Elaborate 拓展**。

**提议（组里倾向这个方向，还没最终拍板）**：拓展不放回对话，而是由个人学习助手承担。

| 5E 阶段 | 在哪里 |
|---|---|
| Engage 引入 | AI 对话：场景 + AI 同学的开场白 |
| Explore 探究 | AI 对话：学生讲，AI 同学追问、带误解问、L1～L3 提示 |
| Explain 解释 | AI 对话：学生自己讲清；讲不清的收尾时补充要点原文 |
| Evaluate 评价 | 练习：算掌握度（对话的小结不打分，只做诊断） |
| Elaborate 拓展 | 小助手：**已掌握**的知识点推拓展任务（练习里没做过的“情境应用”题，或换一个更难的场景再和 AI 同学讲一次） |

**要改的地方**：
- 小助手：现在掌握得好的知识点只显示“掌握得好”，没有后续内容；改成给拓展任务。薄弱的知识点照旧给补救方案（看资料 → 再做题 → 再对话）。
- `计划-个人学习助手.md` 第 1.3 节写的“它不算选做 E1”要改成：助手承担 E1 的拓展阶段。
- `费曼对话-流程详解.md` 加一张 5E 对照表。

**汇报时要说明**：标准 5E 是先拓展后评价，这里是**按评价结果分流**：掌握了的去拓展，没掌握的去补救。顺序有调整，要主动讲。

**另外一种做法（备选，没选）**：在对话补充答案之前加一道情境迁移题，每个学生都做，对话里就走完 5 个阶段；代价是每个知识点多 1～2 句。

**还剩的缺口**：换一种说法的泄露查不出来（程序只能抓到要点原文）。不加程序检查，在评测里统计发生频率，答辩时用数字说明。
