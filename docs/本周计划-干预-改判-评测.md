# 本周计划：干预、老师改判、小规模评测

> 第 2 组 · 2026-11-03 · 草稿，确认后开始做
> 目标：主线「学→记→诊→画→荐→干」能完整演示一遍，并拿到第一批真实评测数字。

| 顺序 | 任务 | 做完能看到什么 |
|---|---|---|
| 1 | 干预：预警 + 对症干预 + 看效果 | 老师发现问题 → 确认干预 → 学生去做 → 掌握度变化 → 干预结束或升级 |
| 2 | 老师改判（AI 对话的判定） | 老师觉得 AI 判错了可以改，相关预警跟着更新 |
| 3 | 小规模评测（DeepSeek 真实调用） | 一张结果表：泄露次数、判定一致率、耗时、费用 |

本周不做：不活跃 / 正确率下降两条预警规则（要好几天的数据才能演示）；用 AI 写干预建议（先用模板）；真正的后端登录（另行安排）。

## 一、干预

### 1.1 判断用的数据（全部已有，不新采集）

| 数据 | 表 | 由谁写入 | 看出什么 |
|---|---|---|---|
| 掌握度 | `mastery` | 「诊」：每次交卷后重算 | 哪个知识点不会 |
| 答题记录 + 错误选项说明 | `answer_record` + `exercise.option_notes` | 「记」：交卷时 | 错在哪里（哪种误解） |
| AI 对话话题结果 | `dialogue_topic_state` + `dialogue_session` | AI 对话模块 | 概念是不是真的理解 |
| 全班答题记录 | `answer_record` | 「记」 | 个人问题还是全班问题 |

### 1.2 两层定义：AI 对话考基础概念，练习题考应用

区分问题、选择干预都以这条定义为前提，建课时也按它来出题：

| 层 | 用什么考 | 考什么 | 例子（边界值分析） |
|---|---|---|---|
| **概念层** | AI 对话的话题 | 基础概念：是什么、为什么，学生要用自己的话说出来 | 「下边界应该取哪几个值？为什么？」 |
| **应用层** | 练习题 | 衍生、扩展、变式题：换情境、换数据、换问法，用概念去解题 | 「密码长度 8～16 位，哪组值能同时覆盖上下边界？」 |

为了能按知识点对上两层，**每个 AI 对话话题要关联一个知识点**（`dialogue_topic` 加 `knowledge_point_id`；现有两个话题：「下边界取哪些值」→ 边界测试值的选取，「为什么要测边界附近」→ 边界错误的成因）。练习题本来就关联了知识点。

**两层各自的状态（按学生 × 知识点）：**

| 层 | 好 | 一般 | 不好 | 未测 |
|---|---|---|---|---|
| 概念层 | 最近一次对话里该知识点的话题全部「自己答出」 | 有「提示后答出」，没有「系统讲解」 | 有任何一个话题「系统讲解」 | 还没做过这章的对话 |
| 应用层 | 掌握度 ≥ 0.6 | — | 作答 ≥ 3 次且掌握度 < 0.6 | 作答 < 3 次 |

（「答非所问被跳过」不算进概念层判断，它说明的是态度而不是理解。）

### 1.3 个人问题怎么分：两层组合

| 概念层 | 应用层 | 说明什么 | 问题类型 | 干预 |
|---|---|---|---|---|
| 好 / 一般 | 不好 | 道理懂，但换个情境就用错，通常有固定误区 | **A 应用问题** | 针对误解的变式练习 |
| 不好 | 好 | 题做对了却讲不出道理，可能是蒙对或只记住了套路 | **B 概念问题** | 复习课件 + 重做 AI 对话 |
| 不好 | 不好 | 基础没打好，题自然也做不对 | **A + B：先概念后应用** | 一条干预分两步：先复习 + 重做对话，完成后再做变式练习 |
| 未测 | 不好 | 不知道是概念还是应用的问题 | **先补测** | 先做这章的 AI 对话，做完后系统重新判断属于哪种 |
| 不好 | 未测 | 概念没懂，还没做题 | **B 概念问题** | 同 B |
| 好 / 一般 | 好 / 未测 | 没问题 | 不报警 | — |

顺序原则：**概念在前，应用在后**。概念没懂时直接刷题没有用，所以两层都不好时先补概念。

### 1.4 全部问题和干预一览

| 问题 | 怎么判断 | 对象 | 干预措施 | 谁去做 |
|---|---|---|---|---|
| A 应用问题 | 见 1.3 | 学生 × 知识点 | **变式练习**：挑含该学生主要误解选项的题 + 点出误解的留言 | 学生（线上） |
| B 概念问题 | 见 1.3 | 学生 × 知识点 | **复习 + 重做对话**：本章阅读 / 视频内容 + 重新做 AI 对话 | 学生（线上） |
| A + B | 见 1.3 | 学生 × 知识点 | **先 B 后 A**，同一条干预分两步 | 学生（线上） |
| 先补测 | 见 1.3 | 学生 × 章 | **做 AI 对话**，做完自动重新判断 | 学生（线上） |
| C 全班共同错误 | 见下文 C | 一门课 × 一种误解 | **课上集中讲**，可再给全班布置一道变式题 | 老师（课堂） |
| D 干预无效 | 见下文 D | 学生 × 知识点 | **线下约谈** | 老师（线下） |

所以干预措施一共 **5 种**：变式练习、复习 + 重做对话、补做对话、课上集中讲、线下约谈。前三种学生在线上完成，后两种由老师本人做。每种都可以附一句老师留言。

本轮**不做**、以后可以加的：不活跃提醒（督促回来学习）、正确率下降提醒、同伴互助（让掌握好的同学帮忙）、调整学习路径（例如没过概念层不解锁练习）。

### 1.5 判断条件和数据细节

#### 基础定义

| 名词 | 定义 | 数据来源 |
|---|---|---|
| **全班** | 本课程里至少交过一次练习的学生（现在没有班级表，先这样算） | `answer_record.course_id` 去重 `student_id` |
| **掌握度** | 「诊」已经算好的值：最近 10 次作答的加权正确率，越近权重越大；作答少于 3 次再乘 次数/3 | `mastery.mastery`，`mastery.attempt_count` |
| **误解** | 老师给某道题某个错误选项写的说明文字。文字完全相同就算同一种误解（建题时同一种误解要写成同一句话） | `exercise.option_notes[选项序号]` |
| **当前仍有某误解** | 只看学生在每道题上**最近一次**作答：最近一次选了带这个误解的选项才算；后来做对了就不算 | `answer_record` 每人每题取 `submitted_at` 最新一条 |
| **一次章节对话** | 学生在某章的一个 `dialogue_session`；只看**最近一次已结束**（`status = FINISHED`）的那次 | `dialogue_session` |
| **系统讲解的话题** | 话题结果为 `REVEALED`（答错 2 次或卡住 2 次，系统直接讲解）。`SKIPPED_IRRELEVANT`（答非所问被跳过）不算，它说明的是态度而不是理解 | `dialogue_topic_state.result` |
| **扫描时机** | 老师打开「干预管理」页时扫描一次；学生交卷、对话结束后也扫描该学生（只用于判断干预是否完成） | — |

#### 每种问题：判断条件、证据、干预、完成、效果

#### A　应用问题（对象：一个学生 × 一个知识点）

| 项 | 定义 |
|---|---|
| 判断条件 | 应用层「不好」（`attempt_count ≥ 3` 且 `mastery < 0.6`）且概念层「好 / 一般」，见 1.3。要求至少 3 次，是因为少于 3 次时掌握度被人为压低，做对 2 次也只有 0.67 |
| 级别 | `mastery < 0.4` 高；`0.4 ≤ mastery < 0.6` 中 |
| 主要误解 | 该学生在这个知识点的题上「当前仍有」的误解里，出现次数最多的一个；出现 ≥ 2 次才算"错因明确"，否则为空 |
| 给老师看的证据 | 掌握度、作答次数 / 答对次数、最近 5 次作答（题目、所选选项、对错）、主要误解 |
| 系统建议 | 布置 2–3 道题：① 先选**含主要误解选项**、且该学生还没做对过的题；② 不够时用该知识点上没做过或做错过的题补足（沿用推荐算法的排序）。留言模板：「你在『{知识点}』上几次都{误解}，做这几道题时注意这一点。」错因不明确时留言改为「『{知识点}』还不稳，做这几道题巩固一下。」 |
| 完成条件 | 布置的每道题，学生在干预通过之后都至少交过一次（不要求全对，否则做不对就永远不结束，也就无法判断无效） |
| 效果 | 完成时的掌握度 − 建立干预时的掌握度，显示为「0.35 → 0.72」 |
| 有效 / 无效 | 完成时 `mastery ≥ 0.6` 为有效；仍 `< 0.6` 为无效，生成 D |

#### B　概念问题（对象：一个学生 × 一个知识点）

| 项 | 定义 |
|---|---|
| 判断条件 | 概念层「不好」：该学生在这一章最近一次已结束的对话里，关联这个知识点的话题有「系统讲解」；应用层为「好」或「未测」，见 1.3（应用层也不好时归为 A + B） |
| 级别 | 中 |
| 给老师看的证据 | 这个知识点的话题：标题、结果、答错次数、卡住次数；可展开看完整对话记录（老师在这里改判，见第二部分）；应用层的掌握度和作答（如果有） |
| 系统建议 | ① 复习本章的阅读 / 视频内容项（`chapter_item.type` 为 doc 或 video）；② 重做本章 AI 对话。留言模板：「第 {n} 章的对话里有 {k} 个问题没能自己答出来，先复习『{内容项}』再重新聊一次。」 |
| 完成条件 | 干预通过之后：布置的内容项都有 `finish_item` 记录，**并且**这一章有一次新的已结束对话 |
| 效果 | 前后两次对话里这个知识点的话题结果，显示为「系统讲解 → 自己答出」 |
| 有效 / 无效 | 新对话里这个知识点的话题不再是「系统讲解」为有效；仍是为无效，生成 D |

**A + B**：同一条干预分两步，第一步按 B（复习 + 重做对话），第一步完成后才把 A 的变式练习推给学生；两步都完成后按应用层掌握度判断有效 / 无效。

**先补测**：干预内容只有「做本章 AI 对话」，完成后系统重新按 1.3 判断，可能转成 A、B 或不再报警；它本身不判断有效 / 无效。

#### C　全班共同错误（对象：一门课 × 一种误解）

| 项 | 定义 |
|---|---|
| 分母 | 全班中，**做过含这个误解选项的题**的学生人数 |
| 分子 | 其中「当前仍有」这个误解的学生人数（一人只算一次，不按次数算） |
| 判断条件 | 分子 ≥ 5 **且** 分子 / 分母 ≥ 30% |
| 级别 | 分子 / 分母 ≥ 50% 高；否则中 |
| 给老师看的证据 | 误解原文、比例「6 / 10 人」、涉及哪几道题、所属知识点、有这个误解的学生名单 |
| 系统建议 | 课上集中讲，讲解要点用相关题目的解析（`exercise.analysis`）；可选：给分母里的全部学生布置一道含这个误解选项、他们还没做对过的题 |
| 完成条件 | 老师点「已在课上讲」；如果布置了题，另外按 A 的完成条件逐个学生统计 |
| 效果 | 处理之后再统计一次比例（只看处理之后的作答），显示为「60% → 20%」；处理之后作答的人数不到 5 人时显示「数据还不够」 |
| 有效 / 无效 | 比例降到 30% 以下为有效；不降不生成 D（全班问题不升级为约谈），只在页面上标出来 |

#### D　干预无效（对象：一个学生 × 原来的知识点或章节）

| 项 | 定义 |
|---|---|
| 判断条件 | A 或 B 的干预**完成**时判为无效（见上面 A、B 的"有效 / 无效"） |
| 级别 | 高 |
| 给老师看的证据 | 原来的预警和干预内容、前后数据（掌握度或讲解话题数）、学生做了哪些题 / 对话记录 |
| 系统建议 | 线下约谈（只记录，不推给学生）；老师也可以改成再布置一轮线上干预 |
| 完成条件 | 老师手动点完成，写一句约谈结果 |

### 1.6 去重：什么时候不再生成预警

| 规则 | 不重复生成的条件 |
|---|---|
| A、B | 同一学生、同一对象已有：待处理的预警，**或**待审核 / 执行中的干预 |
| A、B 再次出现 | 上一轮干预结束（有效或已转 D 并处理）之后，只有**之后的新作答 / 新对话**又满足条件，才重新生成 |
| C | 同一门课、同一种误解已有待处理的预警；处理后，只用处理之后的作答重新统计 |
| D | 每次无效的干预只生成一条 |

老师忽略的预警：同一对象 7 天内不再生成（避免一直弹出），7 天后条件还满足再生成。

### 1.7 谁决定、状态

所有干预都是**系统建议、老师确认**，系统不会自己对学生做任何事。老师可以：通过 / 修改后通过（换题、改留言）/ 驳回 / 忽略预警 / 自己新建干预。

- 预警：待处理 → 已处理（建了干预、已在课上讲、改判后不成立）/ 已忽略
- 干预：待审核 → 执行中 → 已完成（记下有效或无效）；待审核 → 已驳回

### 1.8 存哪些数据

**`alert`**：`course_id`、`student_id`（C 为空）、`rule`（A / B / C / D）、`target_type`（knowledge_point / chapter / misconception）、`target_id` 或 `target_text`（误解原文）、`level`、`message`（给老师的一句话）、`evidence`（判断时的数据快照，JSON，之后数据变了也能看到当时为什么报警）、`status`、`handled_at`、`handled_note`、`created_at`

**`intervention`**：`alert_id`、`course_id`、`student_id`（C 布置全班题时每个学生一条）、`type`（PRACTICE 变式练习 / REVIEW 复习 + 重做对话 / REVIEW_PRACTICE 先复习后练习 / DIALOGUE 补做对话 / CLASS 课上讲 / OFFLINE 约谈）、`step`（REVIEW_PRACTICE 进行到第几步）、`exercise_ids`、`item_ids`、`note`（给学生的话）、`source`（system / teacher）、`status`、`before_value`（建立时的掌握度 / 讲解话题数 / 比例）、`after_value`（完成时的值）、`effective`（有效 / 无效）、`reviewer_id`、`reviewed_at`、`completed_at`

## 二、老师改判

**改什么**：AI 对话的话题结果。练习题是单选、按标准答案判分，不需要改；AI 对话由模型判断答对 / 部分对 / 答错，有可能判错。

**怎么改**：
- 在「干预管理」里，问题 B 的预警直接显示这个学生在本章的对话记录，每个话题标着结果；
- 另有一个「对话判定」列表，可以按"系统讲解"筛选，逐条查看；
- 老师点「改判」，选新的结果（如"系统讲解"改成"提示后答对"），写一句理由；
- 保留原结果、新结果、改判人、理由和时间，不覆盖原始记录；
- 改判后重新扫描：问题 B 的预警如果不再成立，自动标为已处理并注明"改判后不成立"。

**要改的地方**：`dialogue_topic_state` 加改判字段（或新表 `judgement_override`）；后端改判接口；前端改判对话框。

## 三、小规模评测

用 DeepSeek（`deepseek-flash`，关闭思考）真实跑一轮，结果写进 `docs/eval/`。

| 测什么 | 测试集 | 规模 | 怎么判 |
|---|---|---|---|
| 会不会泄露答案 | 学生直接要答案、换说法套答案的消息 | 约 20 条 | 回复里出现还没答到的要点原文 = 泄露 |
| 判定准不准 | 已知正确判定的学生回答（全对 / 部分对 / 答错 / 要答案 / 无关） | 约 30 条 | 模型判定和预设判定一致的比例 |
| 快不快、贵不贵 | 以上全部 | — | 平均 / 最慢耗时，总费用 |

- 测试集由我们自己构造，标明"构造样例"；每条写好预期结果，组员复核；
- 跑评测的程序只在手动运行时才调用真实接口，平时的自动测试仍然用假的 AI，不花钱；
- 预计费用不到 0.2 元。
