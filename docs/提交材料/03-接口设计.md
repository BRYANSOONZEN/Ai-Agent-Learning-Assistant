## 一、总体约定

### 1.1 基本信息

| 项目 | 约定 |
|---|---|
| 风格 | REST + JSON；所有接口以 `/api` 开头 |
| 后端地址 | 开发时 `http://localhost:8080`；前端开发服务器（5173）把 `/api` 代理到后端 |
| 编码 | UTF-8；时间格式 `yyyy-MM-dd HH:mm:ss`（东八区） |
| 文件上传 | `multipart/form-data`，字段名 `file`（视频、课件 PDF） |
| 分页 | 请求 `?page=1&size=10`；返回 `{"records": [...], "total": 35}`；课程列表每页最多 50 条 |

### 1.2 统一返回格式

所有接口都返回同一种结构（`common/Result.java`）：

```json
{ "code": 200, "message": "ok", "data": { ... } }
```

前端 `src/api/request.js` 统一处理：`code == 200` 取出 `data`；否则弹出 `message`；`401` 时清掉登录状态、回到登录页。

### 1.3 错误码

| code | 含义 | 什么时候出现 |
|---|---|---|
| 200 | 成功 | — |
| 400 | 请求不对 / 业务规则不允许 | 参数缺失、格式错误、校验失败；业务规则拒绝，例如“这一项还没解锁，请先完成：《…》”“截止时间已过”“先完成本章的 AI 对话和练习” |
| 401 | 没登录或登录失效 | 没带令牌、令牌签名不对或过期、账号被删除或禁用 |
| 403 | 没有权限 | 角色不对（例如学生调老师接口）、操作别人的课程；权限表里没有的接口一律 403 |
| 404 | 不存在 | 资源不存在、课程没发布、接口路径不存在 |
| 405 | 请求方法不支持 | 例如对只读接口发 POST |
| 409 | 冲突 | 用户名已存在等 |
| 429 | 尝试次数过多 | 同一个用户名连续输错 5 次密码，15 分钟内再登录（密码对了也不行） |
| 500 | 服务器错误 | 未预料的异常；只返回“服务器错误，请稍后重试”，详细原因只写进后端日志 |

### 1.4 登录和权限

1. **登录**：`POST /api/auth/login`，请求 `{"username": "...", "password": "..."}`，返回 `{"token": "...", "expiresIn": 86400, "user": {"id", "username", "name", "role"}}`。
2. **令牌**：JWT（HS256），有效 24 小时；之后每个请求带请求头 `Authorization: Bearer <token>`。视频、课件文件的地址可以用 `?token=` 传（`<video>` 标签没法带请求头）。
3. **防猜密码**：同一个用户名连续输错 5 次，锁 15 分钟；登录成功清零。
4. **每个请求先过拦截器**（`auth/security/AuthInterceptor`）：
   - 查权限表 `AccessRules`：从上往下第一条匹配的规则生效；公开接口直接放行；**表里没有的接口一律拒绝**；
   - 验证令牌签名和过期时间；
   - 再查一次数据库：账号被禁用或删除，旧令牌立即失效；
   - 令牌里的版本号要和账号当前的版本一致：退出登录、改密码、管理员重置密码后版本加 1，旧令牌立即失效（401“登录已失效”）；
   - 角色不在规则里返回 403；
   - 令牌剩不到 2 小时时，响应头 `X-Refresh-Token` 里带一个同样长度的新令牌，前端自动换上（一直在用的人不会中途被踢出）。
5. **登录选项**：登录时 `remember: true` 发 7 天的令牌；管理员开的账号或重置过密码的，返回 `user.mustChangePassword = true`，前端先弹出改密码。
6. **数据权限**在业务层再检查一次：老师只能改自己的课；学生只能看到已发布的课程和章节，只能读写自己的记录。

### 1.5 权限矩阵（`AccessRules.RULES`）

| 路径 | 谁能调 |
|---|---|
| `/api/auth/login`、`/api/auth/register`、`/api/auth/demo-accounts`、`/api/auth/demo-login` | 不用登录（演示切换在配置里关掉后，后两个返回空 / 403） |
| `/api/auth/**` | 登录即可（当前用户、改密码） |
| `/api/admin/**`、`/api/ai/logs/**` | 管理员 |
| `/api/learn/**`、`/api/dialogue/**`、`/api/recommendations/**`、`/api/assistant/**`、`/api/diagnosis/me`、`/api/profiles/me/**` | 学生 |
| `/api/materials/**` | 学生、老师（资料文件：老师预览、学生学习） |
| `/api/courses/**`、`/api/chapters/**`、`/api/chapter-items/**`、`/api/chapter-kps/**`、`/api/knowledge-points/**`、`/api/exercises/**`、`/api/teacher/**`、`/api/diagnosis/**`、`/api/profiles/**`、`/api/class-analysis/**`、`/api/class-issues/**`、`/api/class-pushes/**` | 老师 |

`AuthSecurityTest` 会检查每个接口都有对应的规则，新加接口忘了写规则测试就会失败。

### 1.6 和大模型有关的接口的共同规则

- 大模型的 API key 只在后端配置（`application-local.yml` 或环境变量 `LLM_API_KEY`），前端和接口返回里都没有。
- 每次调用大模型都写一条 AI 调用记录（任务名、输入 / 输出 token、耗时、费用、成功或失败），管理员用 `GET /api/ai/logs` 查看。
- 大模型返回格式不对时重试 1 次；仍不对返回 400，提示老师“再点一次生成”。
- 学生端拿到的题目**不带答案**；交卷后才返回答案和解析。小助手、AI 对话的回复在返回前由程序检查是否泄露答案。

## 三、关键接口示例

### 3.1 学生打开一门课的学习页

`GET /api/learn/courses/1`

```json
{
  "code": 200, "message": "ok",
  "data": {
    "course": { "id": 1, "name": "软件测试", "teacher": "李老师" },
    "chapters": [ { "id": 3, "title": "智能测试生成与优化",
                    "items": [ {"id": 5, "type": "video", "title": "视频 6-1 自动化测试"},
                               {"id": 33, "type": "dialogue", "title": "AI 对话：讲给同学听"},
                               {"id": 65, "type": "exercise", "title": "练习：智能测试生成与优化"} ] } ],
    "doneItemIds": [5],
    "lockedItemIds": [33, 65],
    "progress": { "5": { "watchedSec": 1490.0, "progress": 0.97, "completed": true } }
  }
}
```

`lockedItemIds` 按解锁规则实时计算：视频、文档不锁；AI 对话要本章视频、文档全部学完；练习要本章 AI 对话全部完成。

### 3.2 学生交卷

`POST /api/learn/items/65/submit`

```json
{ "answers": { "101": "A", "102": "AC", "103": "B|C", "104": "需求和代码都要看……" } }
```

返回每道题的对错、得分、正确答案和解析，以及这次交卷后知识点掌握度的变化：

```json
{ "code": 200, "data": {
    "total": 4, "correct": 2, "pending": 0, "score": 0.63,
    "results": [ { "id": 101, "type": "single_choice", "chosen": "A", "answer": "A", "correct": true,
                   "score": 1.0, "analysis": "……", "status": "graded" } ],
    "masteryChanges": [ { "knowledgePointId": 12, "name": "测试用例自动生成", "color": "green" } ] } }
```

- 交卷前不返回答案；没作答的题算错。
- 简答题由程序先判（去掉空格和标点后少于 5 个字 → 0 分；和参考答案完全一样 → 1 分），其余交给大模型判两次；两次不一致时 `status = "pending"`，等老师确认，不算进掌握度。

### 3.3 学生在 AI 对话里说一句

`POST /api/learn/feynman/{sessionId}/reply`，请求 `{"text": "学生说的话"}`，返回整个对话的最新状态 `SessionView`：

```json
{ "code": 200, "data": {
    "id": 18, "status": "open", "kpIdx": 0,
    "kps": [ { "name": "测试用例自动生成", "peer": "阿哲", "phase": "talk", "turns": 3, "maxTurns": 10,
               "clear": 1, "total": 2,
               "points": [ { "no": 1, "status": "clear", "how": "self" }, { "no": 2, "status": "partial", "how": null } ] } ],
    "messages": [ { "role": "student", "content": "……", "kpIdx": 0 },
                  { "role": "peer", "content": "……", "kpIdx": 0 } ] } }
```

返回里没有要点原文和判断标准，只有每条要点的状态（讲清楚 / 不完整 / 讲错 / 没讲到）。

### 3.4 老师查看一次练习的全班分析

`GET /api/class-analysis?courseId=1`：这门课每次练习的全班分析。练习到了截止时间或全部学生都交完才分析；交卷人数不到 80% 的这次分析作废。返回规则①（全班 ≥ 80% 做错的题，提示老师检查题目）和规则②（某条要点在某种考查类型上错误率 > 50%）的结果。老师对规则①的题点“没问题 / 已修正 / 作废 / 忽略”（`POST /api/class-issues/{id}/ok` 等），对规则②的问题生成补充讲解和新题，用 `POST /api/class-pushes` 推送给做错的学生。
