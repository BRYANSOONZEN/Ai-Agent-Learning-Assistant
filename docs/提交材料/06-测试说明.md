## 一、测试分几层

| 层 | 测什么 | 怎么做 | 进不进 CI |
|---|---|---|---|
| ① 后端自动测试 | 业务规则、判分、掌握度、解锁、权限、对话规则、全班分析、画像、小助手 | JUnit 5 + Spring Boot Test + MockMvc；H2 内存库 + `data.sql` 演示数据；**大模型换成假的 `FakeAiClient`**，资料处理服务换成假的 `FakeExtractor` | 进，每次推送都跑 |
| ② 前端检查 | 代码规范、能不能打包 | ESLint + Vite build | 进 |
| ③ 真实大模型测试 | 提示词效果：识别知识点的出处和稳定性、出题有没有歧义、简答判分、聊天会不会泄露答案、费用和用时 | `tools/` 下的独立脚本，调用真实 DeepSeek，结果写进各自的“验证结果”目录 | 不进（要花钱、结果不固定） |
| ④ 端到端检查 | 后端全部主要接口串起来跑一遍，并用独立算法重算掌握度、预警等数字比对 | `tools/e2e/e2e_check.py`，对着运行中的后端（新的演示数据） | 不进 |
| ⑤ 浏览器验证 | 页面能不能用、显示对不对 | 每次改了页面，在浏览器里按流程点一遍，截图存证；界面截图见《界面设计说明书》 | 不进 |

**为什么单元测试不用真实大模型**：真实模型每次回答不一样、要联网、要花钱，测试结果不可重复。`FakeAiClient` 按顺序返回事先写好的回复，并记下收到的请求，所以测试既能检查“程序怎么处理模型的回答”（例如格式不对时重试、摘的原话核对不上时不算），也能检查“发给模型的提示词里有没有该有的内容”（例如补练题的提示词里写的是这个学生自己的错）。

## 二、怎么运行

```powershell
cd backend
.\mvnw.cmd test
```

```powershell
cd frontend
npm run lint
npm run build
```

- 后端测试不需要 API key、不联网；全部跑完约 1～2 分钟。
- 每个测试类有独立的 Spring 上下文（`@DirtiesContext`），互不影响。
- 持续集成：`.github/workflows/ci.yml`，每次推送和 PR 都在 GitHub Actions 上跑后端测试、前端 lint 和打包。
