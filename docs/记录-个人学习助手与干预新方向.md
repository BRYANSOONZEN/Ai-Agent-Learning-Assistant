# 开发记录：个人学习助手（第一版）+ 干预新方向

> 对应计划：`docs/计划-个人学习助手.md`。这一版做了计划第 12 节的第 1、2、5 步，**全部用规则和模板，还没有调大模型**。
> 写于 2026-11-11。**还没有 commit**，等组内看过效果再决定。

---

## 一、这次做了什么（一句话）

- **学生端**：页面右下角多了一个“学习助手”图标，点开能看到**只属于自己的**学习情况；学完一章后给出个人总结：哪些知识点稳了、哪些薄弱、为什么、下一步怎么补。
- **老师端**：干预改成“**个人问题系统自动处理，全班问题提醒老师**”。A、B 两类自动推给学生，老师可以撤回；A + B 仍等老师审核；某知识点全班薄弱的人太多时，单独出一条**全班预警**。
- **顺手修了一个 bug**：打开干预页时，同一条预警会被建两次。

---

## 二、为什么要改

1. 个人干预要老师逐条审核才推给学生。全班几十人、每人十几个知识点，老师审不过来；老师不点，学生就收不到。
2. 学情诊断页的全班统计和干预页的个人预警是分开的，老师看不出是个别学生的问题还是全班的问题。
3. 学生学完一章后，系统其实已经知道他哪里稳、哪里薄弱、错在哪种误解，但没有地方告诉他。
4. 推荐和老师布置藏在“学习推荐”页，学生不点进去就看不到。

## 三、学生端：个人学习助手

### 3.1 学生看到什么

| 学生的情况 | 助手显示 |
|---|---|
| 一章都没开始 | “你还没开始学习”，按钮去选课 |
| 一章学到一半 | 进度（如 2 / 3 项），“继续：下一项的名字”按钮 |
| **一章学完** | **个人总结**：一句话总评 + 每个知识点一张卡片（结论标签、原因、按钮） |
| 有布置给自己的任务 | “给你布置的任务”：哪个知识点、做什么、给你的话；标明是“老师布置”还是“系统根据你的情况布置” |

### 3.2 什么算学完一章

**这一章所有学习项都完成过一次。** 系统本来就在记录每个学习项的完成（`learning_event` 表里的 `finish_item`）：文档打开就算，视频播完，练习交卷，AI 对话结束。没有新建表。

### 3.3 个人总结怎么算

每个知识点用**和干预完全相同的两层判断**（`LayerService`）：

- 概念层：AI 对话里考这个知识点的话题（自己讲出 / 提示后讲出 / 讲解后仍不会或跳过 / 没考到）
- 应用层：练习掌握度（作答不到 3 次算未测，≥ 0.6 算好）
- 再加上**反复出现的误解**：同一个误解至少出现 2 次才算（`InterventionService.mainMisconception`）

| 结论 | 条件 | 标签 | 按钮 |
|---|---|---|---|
| good | 练习好（对话好或没考到） | 稳了 | 无 |
| apply | 练习差，对话不差 | 会讲不会用 | 去做题 |
| concept | 对话差，练习不差 | 概念没讲出来 | 巩固一下（AI 对话） |
| both | 两层都差 | 两边都不稳 | 巩固一下（AI 对话） |
| few | 对话好，但练习不到 3 次 | 练得太少 | 去做题 |
| none | 两层都没数据 | 数据不够 | 视情况 |

例：学生03 学完第 1 章后，知识点「边界测试值的选取」显示：

> 对话里你自己讲出来了，但练习掌握度 0.22，几次都是这个问题：只取了边界和内侧，缺少越过边界的值。做几道题把它用熟。

### 3.4 什么时候隐藏

- **做练习时（交卷前）**：隐藏，防止拿它当作弊工具；交卷后出现。
- **AI 对话进行中**：隐藏，不和对话抢角色；对话结束后出现。
- 实现：`stores/assistantFocus.js`，练习和对话组件进行中时“占住”，结束或离开时“放开”。

### 3.5 图标上的数字

新学完的章节、新布置的任务各算一个；点开面板后清零（记在浏览器 `localStorage` 里）。

### 3.6 数据边界

助手接口**只返回这个学生自己的数据**：进度、两层结论、掌握度、他自己反复出现的误解。**不返回**题目标准答案、话题要点和讲解、其他学生的任何数据、姓名。测试里专门检查了返回内容（第六节）。

## 四、老师端：干预新方向

### 4.1 改了什么

| | 以前 | 现在 |
|---|---|---|
| A（会讲不会用） | 等老师审核 | **系统自动推给学生**，老师可撤回 |
| B（概念没讲出来） | 等老师审核 | **系统自动推给学生**，老师可撤回 |
| A + B（两层都差） | 等老师审核 | **仍等老师审核**（问题较重） |
| A 但这个知识点下没有题可布置 | 等老师审核 | 仍等老师审核 |
| 什么时候扫描 | 老师打开干预页时 | 老师打开干预页时 **+ 学生打开助手或“老师布置”时**（只扫他自己） |
| 全班情况 | 只在诊断页看统计 | **全班预警**：干预页最上面，按章节分组 |
| 干预记录 | 执行中 / 已完成 | 多了“已撤回”，并标明“系统自动”还是“老师审核” |
| 侧边栏数字 | 待处理的个人预警 | 全班预警 + 待审核的个人预警 |

判断、分类、挑题、判断效果的规则**一条都没改**。

### 4.2 全班预警

直接用学情诊断页已经算好的全班统计，不存表：

- 练过这个知识点的学生 **≥ 5 人**（太少比例不可信）
- 薄弱人数 / 练过人数 **> 30%**

满足就报，并附最常见的错因。演示数据里：「边界测试值的选取」7 人练过、4 人薄弱（57%），最常见错因“只取了边界和内侧，缺少越过边界的值”。

**怎么调**：`InterventionService` 里的 `CLASS_WEAK_RATIO`（0.3）和 `CLASS_MIN_PRACTICED`（5）。

### 4.3 撤回

老师在干预记录里点“撤回”：

- 学生那边“给你布置的任务”里不再显示；
- 还没做的题交回系统推荐，之后照常按薄弱知识点推；
- 撤回后学生没有新数据，不会马上又自动建一条。

### 4.4 开关

`application.yml` 里设 `platform.intervention.auto-approve: false`，就回到“全部由老师审核”的旧做法。不写就是自动。旧的 13 个干预测试就是在这个开关关掉的情况下跑的，保证旧流程仍然正确。

### 4.5 修复：重复预警

**原因**：老师打开干预页时，页面的 `board` 和侧边栏的 `open-count` 两个请求同时到达，各自扫描一遍，都发现“还没有预警”，于是各建一条。

**做法**：扫描前先拿一把锁（`InterventionService.SCAN_LOCK`），一次只让一个请求扫描。锁加在控制器里、事务外面，保证前一次扫描提交之后，下一次才开始读。学生端的扫描也用同一把锁。

**验证**：测试里同时发 4 个请求（2 个 board、2 个 open-count），结果仍是 3 条预警、3 条干预。

## 九、第二轮：端到端检查（2026-11-11）

**为什么做**：自动化测试用的是假模型，测的是单个接口。还需要对着**真正运行的系统**把主要接口串起来调一遍，用独立的计算核对数字，并真的调几次模型。

**做法**：`tools/e2e/e2e_check.py`。每次从干净的种子数据开始，共 50 项检查：

| 部分 | 检查什么 |
|---|---|
| 登录 | 正确密码能登录；密码错和用户不存在给同一个提示；真实模型已配置 |
| 学习、作答 | 学生只看到已发布课程和章节；下发题目不带答案；交卷判分；选错时有误解说明；**掌握度用脚本里独立实现的公式复算，和系统一致** |
| 推荐 | 总数 ≤ 5、每个知识点 ≤ 3；每道都有理由；做错的排前面 |
| AI 对话（真实模型 5 轮） | 没作答就要答案时不给答案；完整作答后进入下一步；回复不超过 120 字；每次调用都记日志、都成功、有耗时和费用 |
| 学习助手 | 学完判断；**总结结论和两层判断的规则一致**（脚本里独立实现一遍再比）；不含答案和其他学生 |
| 干预 | A 自动执行、A+B 不自动；并发扫描不重复；**全班预警 = 诊断统计按阈值筛出来的**；做完题后判为有效（0.22 → 0.70）；撤回、不能重复撤回、撤回后不马上重建 |

**第一次结果：50 项里 49 项通过。** 有一项不通过，另外还发现了一个问题：

1. **测试本身的问题**：只通过接口交卷不会记“学习项完成”（这条记录由页面发送），所以助手不算学过。这是对的，改了测试。
2. **真问题**：学生把三项都点完了，但练习不到 3 次、对话没结束，两层都是“数据不够”。总结第一句却写成“2 个知识点没有明显薄弱的，有的再练几道会更稳”，听起来像都没问题；而且“数据不够”的知识点没有按钮。
   - 改法：都没有足够数据时写“都还没有足够的数据判断，先把练习多做几道”；“数据不够”也给“去做题”按钮。
   - 新增自动化测试 `finishedButNoData_saysSoAndSuggestsPractice`，防止再出现。

**改完后：端到端 50 项全部通过；自动化测试 96 个全部通过。** 5 轮真实对话共花 0.0127 元，平均每轮约 1.2 秒。

## 十一、第四轮：视频处理原型，用开放视频实测（2026-11-11）

完整记录：`tools/video_to_text/README.md`。要点：

- **只做成独立脚本，还没接进平台。**
- **测试视频**：Wikimedia Commons 上的 2 个开放许可视频，一个只有背景音乐，一个是有讲解的新闻。
- **验证结果**：
  - 超大、超长、损坏的文件都能拦住。
  - 没有讲解声音的视频会提示老师。
  - 识别速度约 1 倍速。
  - 加上章节专业词提示后，专业词写对次数从 0 次升到 10 次。
  - 用真实模型问了 4 个问题，全部答对、时间点正确；视频里没讲的会回答“没有讲到”。
- **过程中发现并改掉的问题**：
  - 超大文件会让程序崩溃。
  - 关掉静音过滤，模型会编出假字幕。
  - 关键词检索对不上同义词，改成文字不长时全部交给模型。
  - 模型输出上限太小，回答为空。
  - API key 带引号，读取失败。
- **新装的 Python 包**：`faster-whisper` 及其依赖，识别模型 small 约 480 MB，缓存在本机 Hugging Face 目录。

## 十二、第五轮：计算机课程实测 + 重叠和标知识点（2026-11-11）

**为什么做**：前面测的视频不是计算机课。这次按组内要求，换成计算机课程再测，并加上组内决定的两项改进：段间重叠、标知识点。

- **测试视频**：
  - MIT《The Missing Semester》调试与性能分析，英文，CC BY 3.0。
  - 南京大学《操作系统：设计与实现》第 1 讲，中文。它没有标注许可，只在本机测试，不放进仓库。
  - 两个完整视频都超过 200 MB，操作系统那条还超过 60 分钟，都被拦下。模拟老师分段，各取 10 分钟。
- **重叠**：每段带上前一段的最后一句，单独存放，这一段自己的时间点不变。
- **标知识点**：规则改了三次才和内容对得上：
  1. 名称里共有的词（如“操作系统”）不算。
  2. 由几部分组成的名称拆开来匹配。
  3. 只剩一个常见词的部分不能单独算数。
- **新发现，已改**：
  - 用中文问英文课，一段都检索不到。改成走检索时先让模型把问题改写成视频所用语言的关键词，改完后全部答对。
  - 用 `python -I` 运行时找不到同目录的模块。
  - 英文句子之间没有空格。
  - 切词原来不适合英文。
- **结果**：两门计算机课一共问了 10 个问题，全部答对、时间点正确；两道“这段没讲”的题都回答“没有讲到”，模型没有用自己的知识补充。
- **耗时**：
  - 识别：10 分钟的课用 8～12 分钟，只在上传时做一次。
  - 分段、重叠、标知识点：每次 12 毫秒。
  - 学生提问：1.5～4 秒。
- **详细记录**：`tools/video_to_text/README.md` 第 4.5 节。

## 十三、第六轮：识别引擎换成 SenseVoice（2026-11-11）

**为什么换**：Whisper 太慢，15 分钟的中文课要 12～18 分钟。组内决定先试开源的 SenseVoice（阿里），它一次输出整句，不是一个字一个字地生成。

**改动**：
- `video_to_text.py` 加了 `--engine` 选项：默认 `sensevoice`，`whisper` 留作备用。后面的分段、重叠、标知识点、问答都没有改。
- 静音检测切出的每一小段最长 15 秒。不限时平均 28 秒一段，时间点太粗。
- 去掉语气词。SenseVoice 会把“嗯、呃”全记下来，10 分钟里有 68～77 个。
- 新装：`torch`、`torchaudio`（CPU 版）、`funasr`，SenseVoice 模型 936 MB。

**结果**（同一台笔记本 CPU，同样的 10 分钟片段）：

| | Whisper | SenseVoice |
|---|---|---|
| 中文操作系统课 | 712～726 秒 | **112 秒** |
| 英文 MIT 课 | 484～487 秒 | **101 秒** |
| 15 分钟中文课（推算） | 约 18 分钟 | **约 3 分钟** |
| 中文专业词 | 要加提示才行 | 不用提示，“肾结石”“肾脏”更准 |
| 问答 | — | 中文 4 题全对，“点名”题比 Whisper 版答得更全；英文 4 题对 3 题 |

**发现的问题**：SenseVoice 的英文不如 Whisper。printf 认不出来，/var/log 识别成乱码，句号少，导致英文课“系统日志放在哪个目录”这一题没答出来。所以中文课用 SenseVoice，英文课还是 Whisper 更好。组内决定**按课程语言自动选**：中文 SenseVoice，英文 Whisper（`--engine auto`，默认）。已实测：不指定引擎时，中文视频自动用 SenseVoice，英文视频自动用 Whisper。

详细记录：`tools/video_to_text/README.md` 第 4.6 节。
