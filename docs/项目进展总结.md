## 三、第二课：项目启动包（10月10–11日）

### 3.1 做了什么

核心是一次**技术探查（spike）**：用真实AI（Claude Opus 5.5）检验 E1 的关键问题——
"学生要答案时，AI能不能先引导，而且引用的课件确实支持它的说法、不泄露答案？"

| 步骤 | 内容 |
|---|---|
| 材料 | 课件片段 S1–S4（软件测试边界值）；5个构造的学生问题 Q1–Q5（标"模拟"） |
| 第一轮 | 发请求、原样保存输出、按事先定的判据逐条核对 |
| 发现 | Q2 中AI让学生"和S2给出的例子对照自查"，而S2里就是完整答案——**带出处反而泄露答案** |
| 第二轮 | 加规则"只引原理句，作答前不指向含答案的例子"，新开对话重跑 |
| 结果 | 第二轮没有再出现这种泄露；但学生催一次（Q5），AI就给出接近答案的"最高一级提示" |
| 决策 | 修订后继续：接受"先引导＋只引原理句"方向；提示升级上限、课件拆分要继续解决 |

我们也写清了局限：每轮只跑1次、只有5个构造样例、多轮关系是在单条请求里描述的、提示词无法阻止学生自己翻课件。

### 4.4 本轮最小完整流程（第7栏）

同一名模拟学生做"年龄18—60，列出边界测试输入"：

1. 教师上传课件 → 系统拆成原理句/例题 → **教师确认**（人的确认点1）
2. 学生提问 → 程序读取阶段、提示级别、是否已作答 → E1生成提示 → 程序检查禁出现值 {17,19,59,61} 和片段类型 → 通过才显示（M1–M5/M7＋E1）
3. 学生作答 → M5判定正误和错因 → 写入 M6 learning_event → M8 计算掌握度并引用错误证据（E4）
4. 教师在 M10 查看，**可修改判定**（人的确认点2）
5. L3后仍不会 → 系统收尾（参考答案对比＋变式题）→ 看板按错因汇总提醒

本轮不做：课堂实时同步、UML画布和代码编辑器、图片/手写作答、多课程多单元、跨文档完整RAG、M9推荐、E4班级排行、自动决定成绩或干预。（只限本轮，学期内完成必做部分。）

### 4.7 预算与可行性

- 工时：本轮约109人时（开发约96＋人工核对与标注约13）。原按四人可用192人时；现三人可用144人时，仍未超出。
- 调用量：一轮完整评测约451次调用；首版（5轮评测＋同等调试余量）约4,510次调用、1,176万输入、230万输出token。
- 选型条件（同时满足）：
  1. 3,000×P_in ＋ 600×P_out ≤ 50,000（E1每次≤0.05元）
  2. 11.76×P_in ＋ 2.30×P_out ≤ 100（首版总≤100元）
  3. 本地可开通、可付费
  4. P0 真实调用跑通
  5. P5 质量达标（泄露0次、出处支持≥95%）
- 四项红线：数据、成本、时间满足；技术待处理（模型未选定、未跑通 → P0、P5）。
- 探查计划 P0–P5：P0 选模型并真实调用；P1 升级边界；P2 多轮状态一致；P3 稳定性；P4 课件可见性；P5 换模型后是否仍不泄露。
