## 二、现在的规则（全部有数字）

### 2.1 登录 `POST /api/auth/login`

检查顺序：

| 步骤 | 规则 | 失败返回 |
|---|---|---|
| 1 是否锁定 | 同一用户名**连续输错 5 次锁 15 分钟** | 429“密码连续错误 5 次，请 N 分钟后再试”（密码对了也不行） |
| 2 用户名 + 密码 | BCrypt 比对 | 400“用户名或密码错误”；**剩 2 次、1 次时**加“还可以再试 N 次” |
| 3 账号状态 | 1 正常 / 0 禁用；**密码对了才检查** | 403“账号已被禁用，请联系管理员” |
| 4 发令牌 | JWT，**24 小时有效** | — |

- 用户名不存在也照样计数、照样上锁，提示一模一样，所以试不出哪些用户名存在。
- 登录成功清零计数；管理员重置密码或启用账号也会清零。
- 角色不再由前端选，**以数据库里的账号为准**。

### 2.2 令牌（JWT）

| 项目 | 值 |
|---|---|
| 格式 | 头.内容.签名（HS256，用 JDK 自带的 HMAC-SHA256，没加新依赖） |
| 内容 | 用户 id、角色、姓名、签发时间、过期时间 |
| 有效期 | 24 小时（`platform.auth.token-hours`） |
| 密钥 | `platform.auth.jwt-secret` 或环境变量 `JWT_SECRET`；都没配就**每次启动随机生成**（开发阶段数据库也是每次重建，正好一致） |
| 前端保存 | localStorage，每个请求加 `Authorization: Bearer 令牌` |
| 资料文件 | `<video>`、`<a>` 带不了请求头，所以**只有** `/api/materials/**` 允许 `?token=` 放在网址里；别的接口这样传无效（实测 401） |

### 2.3 每个请求的检查（`AuthInterceptor`）

```
请求 → 查权限表 → 公开接口？放行
                → 表里没有？403（默认拒绝）
     → 取令牌 → 没有/签名不对 → 401“请先登录”
              → 过期 → 401“登录已过期，请重新登录”
     → 再查一次数据库 → 账号被禁用/删除 → 401（禁用立即生效，不用等令牌过期）
     → 角色不在规则里 → 403“没有权限访问这个接口”
     → 通过：把当前用户放进本次请求（CurrentUser），业务代码只从这里取
```

前端收到 401：清掉登录状态，回到登录页，并记住原来要去的页面；收到 403：页面顶部提示。

### 2.4 权限表（`AccessRules`，24 条，从上往下第一条匹配生效）

| 谁能调 | 接口 |
|---|---|
| 不用登录 | `/api/auth/login`、`/api/auth/register` |
| 登录即可 | `/api/auth/**`（我是谁、改密码）、`/api/hello/**` |
| 管理员 | `/api/admin/**`（用户管理）、`/api/ai/logs/**`（AI 调用记录） |
| 学生 | `/api/learn/**`、`/api/dialogue/**`、`/api/recommendations/**`、`/api/assistant/**`、`/api/diagnosis/me`、`/api/profiles/me`、`/api/interventions/mine` |
| 学生 + 老师 | `/api/materials/**`（资料文件） |
| 老师 | `/api/courses/**`、`/api/chapters/**`、`/api/chapter-items/**`、`/api/knowledge-points/**`、`/api/exercises/**`、`/api/teacher/**`、`/api/diagnosis/**`、`/api/profiles/**`、`/api/interventions/**`、`/api/alerts/**` |

- **表里没有的接口一律拒绝**；测试 `everyEndpointHasAnAccessRule` 会逐个检查后端所有接口都有规则，新加接口忘了写会直接测试失败。
- 管理员**不能**调老师和学生的业务接口：管理员只管账号和平台。

### 2.5 学生注册 `POST /api/auth/register`

| 字段 | 规则 |
|---|---|
| 用户名 | 4～32 位字母、数字、下划线；重复返回 **409**“用户名「X」已被注册” |
| 密码 | 8～64 位，至少一个字母和一个数字 |
| 姓名 | 必填，≤ 32 字 |
| 角色 | **请求里没有这个字段**，后端一律存成学生；就算请求里塞 `"role":"teacher"` 也没用（有测试） |

注册成功直接发令牌，进入学生首页。前端也按同样规则当场提示，另外检查两次密码是否一致。

### 2.6 管理员：用户管理 `/api/admin/users`

| 功能 | 规则 |
|---|---|
| 列表 | 按角色筛选、按用户名或姓名搜索；每页 10 条（最多 50）；新建的在前；显示“锁定中” |
| 人数 | 老师、学生、管理员、已禁用各多少 |
| 开通账号 | 只能开**老师或学生**；用户名、密码规则同注册；重复 409 |
| 禁用 / 启用 | 禁用后这个人的令牌**下一次请求就 401**，已打开的页面退回登录页；启用同时解锁 |
| 重置密码 | 新密码同样规则；**同时解除锁定** |
| 不能做 | 修改自己、修改任何管理员账号（403），避免把管理员锁在外面 |

### 2.7 修改自己的密码 `PUT /api/auth/password`

所有角色都有（侧边栏头像菜单 → 修改密码）。要输原密码；新密码同样规则，不能和原密码一样。

### 2.8 各角色看到的菜单

| 角色 | 菜单 | 登录后进入 |
|---|---|---|
| 学生 | 首页、课程学习、学习记录、学情诊断、学生画像、学习推荐（6 项） | 首页 |
| 老师 | 首页、我的课程、学情诊断、干预管理（4 项） | 首页 |
| 管理员 | 用户管理、AI 调用记录（2 项） | 用户管理 |

AI 调用记录从老师端移到管理员端（之前讨论过：这是平台管理的事，不是日常教学）。菜单只是隐藏；真正的限制在后端权限表。

### 2.9 每个判断是为了什么

图 T2、T2b 里的每个菱形都是一道关卡，没通过就停在那里，返回对应的提示。

**登录时的三个判断**（回答“你是不是本人、能不能进来”）：

| 判断 | 为了什么 | 为什么放在这个位置 |
|---|---|---|
| ① 锁定中？ | 防止有人一直猜密码。不限次数的话，别人可以写程序把常见密码一个个试过去，迟早试中 | 放在第一步：锁住后连密码都不比对，输对也进不去，才真正挡住猜密码 |
| ② 用户名存在且密码正确？ | 确认是本人，只有知道密码的人能登录 | 用户名不存在和密码错误给同一句提示，别人没法靠提示判断“这个用户名是真的”再专门猜它 |
| ③ 账号状态 | 让管理员能关掉某个账号，例如学生毕业、老师离职、账号被盗 | 放在密码之后：只有密码对的人才看到“已被禁用”，不知道密码的人连账号存不存在都不知道 |

三关都过了才发令牌。

**每个请求的四个判断**（回答“你现在还能不能用、能不能用这个功能”）。登录只发生一次，之后每调一次接口，后端都要再确认一次：

| 判断 | 为了什么 | 不做会怎样 |
|---|---|---|
| ① 查权限表 | 先确定这个接口谁能调；表里没写的一律拒绝 | 以后新加接口忘了设权限，就谁都能调 |
| ② 令牌签名对、没过期 | 确认令牌是我们自己发的、没被改过、还在 24 小时内 | 有人伪造令牌，或把令牌里的“学生”改成“老师”，就能冒充 |
| ③ 再查数据库 | 确认这个账号现在还正常 | 管理员禁用了账号，这个人手上的令牌还能用到 24 小时过期 |
| ④ 角色符合规则 | 确认这个角色能用这个接口 | 学生登录后直接调老师的接口，改课程、看全班数据 |

前端隐藏菜单只是界面上看不到；真正的限制是后端这些判断，绕过页面直接调接口也过不去。

### 2.10 令牌存在哪、怎么判断过期

**关掉页面不用重新登录，24 小时内重新打开都还是登录状态。**

**存在哪**：登录成功后，前端把令牌存进浏览器的 localStorage（本地存储，`se-platform-user`），之后每个请求自动带上 `Authorization: Bearer 令牌`。

| 操作 | 令牌还在吗 |
|---|---|
| 刷新页面 | 在 |
| 关掉标签页再打开 | 在 |
| 关掉整个浏览器、第二天再打开（24 小时内） | 在 |
| 点“退出登录” | 删掉 |
| 换电脑、换浏览器 | 没有，要重新登录 |

**过期时间写在令牌里面**。令牌分三段：头.内容.签名，内容里有：

| 字段 | 含义 | 例子 |
|---|---|---|
| `iat` | 签发时间 | 11 月 22 日 10:00 |
| `exp` | 过期时间 = 签发时间 + 24 小时 | 11 月 23 日 10:00 |

**每次请求，后端拿 `exp` 和现在的时间比**（`JwtService.verify`）：

- 还没到：放行。
- 已经过了：返回 **401**“登录已过期，请重新登录”。前端收到后清掉令牌、跳回登录页，并记住刚才在哪一页（`?redirect=`），重新登录后直接回到那一页。

**过期时间改不了**：`exp` 在签名保护的范围里，改一个字签名就对不上，后端判为假令牌（401）。测试 `expiredTokenIs401WithAClearMessage`、`missingBrokenOrTamperedTokenIs401` 分别验证过期和篡改。

**现在的不足**：令牌签发满 24 小时，不管这个人是不是正在操作，下一次请求都会被要求重新登录（**按签发时间算，不是按最后一次操作算**）。决定**先保留 24 小时**，改进方法见第五节。

**答辩时可以这样说**：
> 令牌存在浏览器本地，关掉页面、关掉浏览器都还在，24 小时内打开不用重新登录。过期时间写在令牌里，并且受签名保护，改不了；后端每次请求都比对过期时间，过期了前端自动回登录页，登录后回到原来的页面。下一步可以加自动续期，让一直在用的人不会被中途踢出去。

## 四、测试

**单元测试：106 个全部通过**（原来 96 个 + 新 `AuthSecurityTest` 10 个）。

| 测试 | 验证什么 |
|---|---|
| loginGivesATokenThatIdentifiesTheUser | 登录拿到令牌，`/me` 认出是谁 |
| missingBrokenOrTamperedTokenIs401 | 没令牌、乱写、把令牌里的 student 改成 teacher → 401 |
| expiredTokenIs401WithAClearMessage | 过期 → 401“登录已过期，请重新登录” |
| eachRoleOnlyReachesItsOwnEndpoints | 三种角色各 3～4 个接口，能调和不能调的都测 |
| currentUserComesFromTheToken | 两个老师看到的课程数不同；学生带演示请求头也冒充不了别人 |
| everyEndpointHasAnAccessRule | 后端所有接口都有权限规则 |
| studentsCanRegisterButNeverAsTeacher | 注册成学生；塞 role 无效；重名 409；弱密码、短用户名 400 |
| fiveWrongPasswordsLockTheAccountUntilAdminResets | 第 3、4 次提示剩几次；第 5 次锁；锁住后密码对也不行；不存在的用户名同样计数；管理员重置后能登录 |
| disablingAnAccountCutsOffItsTokenImmediately | 禁用后旧令牌马上 401，重新登录 403 |
| adminCreatesTeachersButCannotTouchAdmins | 开通老师账号能登录；不能开管理员；不能禁用管理员 |

**浏览器实测**（前后端都真实运行）：

1. 不填 → 输入框下“请输入用户名 / 密码”。
2. 输错 1 次 → 卡片里“用户名或密码错误”，密码框清空。
3. 第 3 次 → “还可以再试 2 次”；第 5 次 → 锁定；再输对的密码 → 仍然“请 15 分钟后再试”。
4. 管理员登录 → 直接进入用户管理；teacher01 显示“锁定中”；重置密码（弱密码当场被拦）→ 锁定解除 → teacher01 用新密码登录成功。
5. 学生03 的令牌能调学生接口，调老师接口 403；管理员禁用学生03 → 这个令牌下一次请求 401“账号已被禁用”，重新登录 403；再启用。
6. 注册：弱密码、两次不一致当场提示；用已有用户名 → “已被注册”；新用户名 → 直接进入学生首页，看到的是自己的空数据。
7. 老师 teacher01：菜单 4 项，我的课程只有自己的 3 门。
8. 学生01：学情诊断、课程学习正常，控制台没有报错。
9. 资料文件：不带令牌 401；网址带令牌通过检查；别的接口在网址里带令牌无效。

## 五、还可以做的（没做）

| 项目 | 说明 |
|---|---|
| 令牌自动续期（建议优先做） | 令牌快过期时（例如剩不到 2 小时），后端在响应里顺便发一个新令牌，前端替换旧的。一直在用的人永远不会被踢；连续 24 小时不用才要重新登录。只改拦截器和前端请求两处 |
| “记住我” | 登录页加勾选框：勾上发 7 天的令牌，不勾发 24 小时。自己的电脑久一点，公用电脑短一点 |
| 退出登录让令牌立即失效 | 现在退出只删前端保存的令牌；令牌本身 24 小时内仍有效。要做就加“令牌黑名单”或“令牌版本号” |
| 锁定计数放到共享存储 | 现在放内存，重启清零；部署多台服务器要换 Redis |
| 学生加入班级 / 选课 | 现在注册后能看到所有已发布课程；`user.clazz_id` 字段已留好 |
| 首次登录强制改密码 | 管理员开的账号用的是初始密码 |
| 演示账号密码 | 种子数据的演示密码比新规则短，只用于演示；新建和修改的密码都按新规则 |
