## 1. 前提：两层定义

| 层 | 用什么考 | 好 | 一般 | 不好 | 未测 |
|---|---|---|---|---|---|
| 概念层 | AI 对话：该知识点的话题，看最近一次已结束对话 | 自己答出 | 提示后答出 | 系统讲解 | 没做过对话 |
| 应用层 | 练习题：`mastery` 表 | 掌握度 ≥ 0.6 | — | 作答 ≥ 3 次且 < 0.6 | 作答 < 3 次 |

| 概念层 | 应用层 | 结果 |
|---|---|---|
| 好 / 一般 | 不好 | **A**：变式练习 |
| 不好 | 好 / 未测 | **B**：复习 + 重做对话 |
| 不好 | 不好 | **A + B**：先做 B，完成后再推 A 的练习 |
| 其他 | | 不报警（"未测 + 不好"属于"先补测"，这次不做） |

## 2. 每一步做什么

### 第 1 步：数据库（`schema.sql`）

| 改动 | 内容 |
|---|---|
| `dialogue_topic` 加列 | `knowledge_point_id`：话题考哪个知识点 |
| 新表 `alert`（预警） | `course_id`、`student_id`、`knowledge_point_id`、`type`（A / B / AB）、`level`（high / medium）、`message`、`evidence`（判断时的数据快照，JSON）、`status`（open / handled / ignored）、`handled_at`、`created_at` |
| 新表 `intervention`（干预） | `alert_id`、`course_id`、`student_id`、`knowledge_point_id`、`type`（PRACTICE / REVIEW / REVIEW_PRACTICE）、`step`（A + B 进行到第几步）、`exercise_ids`、`item_ids`、`note`（给学生的话）、`source`（system / teacher）、`status`（pending / approved / rejected / done）、`before_value`、`after_value`、`effective`、`reviewer_id`、`reviewed_at`、`completed_at`、`created_at` |
| `recommendation` 加列 | `source`（system / teacher）、`intervention_id` |

### 第 2 步：演示数据（`data.sql`）

| 内容 | 安排 |
|---|---|
| 话题关联知识点 | 「下边界取哪些值」→ 知识点 1 边界测试值的选取；「为什么要测边界附近」→ 知识点 2 边界错误的成因 |
| 学生03 → **A** | 对话里知识点 1 自己答出；练习做 4 次，3 次选「缺少越过边界的值」，掌握度约 0.3 |
| 学生04 → **B** | 练习知识点 1 掌握度 ≥ 0.6；对话里知识点 1 系统讲解 |
| 学生07 → **A + B** | 对话里知识点 1 系统讲解；练习掌握度 < 0.6 |
| 学生05、06 → 对照 | 两层都好，不应报警 |
| 学生01（现有） | 作答只有 2 次，属于"未测"，不应报警（验证"至少 3 次"这条） |

### 第 3 步：后端判断（新包 `intervention/`）

- `LayerService`：算一个学生在一个知识点上的两层状态（概念层读 `dialogue_session` + `dialogue_topic_state`，应用层读 `mastery`）。
- `AlertScanner`：对课程里每个学生 × 每个知识点按第 1 节的表判断，生成预警；同一学生 × 知识点已有待处理预警或待审核 / 执行中的干预时，不再生成。
- 每条预警自动配一条**系统建议**（状态"待审核"）：
  - A：主要误解 = 该学生在这个知识点的题上，最近一次作答选中的误解里出现最多的一个（≥ 2 次才算）。先挑含这个误解选项、他还没做对过的题，不够用该知识点上没做过或做错的题补足，共 2–3 道。留言按模板生成。
  - B：本章的阅读 / 视频内容项 + 重做本章 AI 对话。留言按模板生成。
  - A + B：第 1 步同 B，第 2 步同 A。
- 建议和留言都用模板生成，**不调 AI**。

### 第 4 步：后端审核、执行、看效果

| 动作 | 结果 |
|---|---|
| 老师通过（可先改题目、留言） | 状态"执行中"，记下 `before_value`（A：掌握度；B：话题结果）。A 的题写进推荐表（`source = teacher`），排在最前、不占系统推荐的 5 道名额；B 的内容项和对话显示在学生的"老师布置"里 |
| 老师驳回 / 忽略预警 | 干预"已驳回" / 预警"已忽略" |
| 判断完成（在读取干预时检查） | A：布置的每道题在通过之后都交过一次；B：内容项都有 `finish_item`，并且之后有一次新的已结束对话；A + B：第 1 步完成后自动推出第 2 步的题，第 2 步完成才算完成 |
| 记录效果 | 写入 `after_value` 和 `effective`：A 看掌握度是否 ≥ 0.6；B 看该话题是否不再是系统讲解。无效先只标出来，不生成 D |

接口：

```
GET  /api/alerts?courseId=              扫描并返回预警（老师）
PUT  /api/alerts/{id}                   忽略
GET  /api/interventions?courseId=       干预列表，带前后数据
POST /api/interventions/{id}/review     通过（可带修改）/ 驳回
GET  /api/interventions/mine            学生：老师布置的内容
```

学生调用老师接口一律拒绝。

### 第 5 步：后端测试

- 第 2 步的每个学生都被判成预期的类型；对照学生、学生01 不报警
- 扫描两次不重复
- A 挑的题含主要误解选项
- 通过后学生推荐里出现老师布置的题；做完后干预完成，效果正确
- A + B 第 1 步完成后才出现练习
- 学生调用老师接口被拒绝

AI 部分照旧用 FakeAiClient，不花钱。

| 页面 | 内容 |

| 「干预管理」（现在是占位页） | 深色汇总条（待处理 / 执行中 / 已完成）；左边预警列表，标 A / B / A + B 和级别；右边是两层状态、证据（最近作答、误解、对话话题结果）、系统建议，可改题目和留言后"通过"，或"驳回 / 忽略"；下方干预列表带前后数据 |
