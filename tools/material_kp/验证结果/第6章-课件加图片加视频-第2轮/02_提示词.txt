[P4] 自动化测试概述：自动化测试：把以人为驱动的测试行为转化为机器执行的一种过程。自动化测试是一个系统化的过程，其核心是利用专门的软件工具、预定义的脚本或编程代码来控制测试的执行，并将实际结果与预期结果进行比较，从而完成对软件产品的验证。 • 人工定义测试逻辑：编写代码/脚本精确定义测试步骤 • 核心价值：解决测试执行的机械重复问题 • 关键依赖：测试人员的经验与手动干预

[P5] 自动化测试概述：传统自动化测试五大局限性：1. 维护成本高自动化脚本对应用界面（如按钮ID、元素位置）的任何微小变更都极其敏感，这导致频繁的脚本失效与人工修复，随着产品迭代，维护工作可能演变为沉重的负担。 2. 测试覆盖度不足由于测试用例完全依赖于人工设计与编写，其覆盖范围仅限于测试人员预设的场景，难以模拟复杂的用户交互路径或进行随机探索，导致许多边界和深层缺陷被遗漏。 3. 测试数据准备困难构造和管理符合测试场景的特定数据（如用户状态、业务流程数据）过程复杂且易错。人工准备的数据往往过于和理想化，无法真实模拟生产环境的复杂性，使得某些数据依赖型缺陷难以被发现。
[P6] 自动化测试概述：传统自动化测试五大局限性：4. 脚本创建效率瓶颈从需求分析到脚本编写、调试的整个过程高度依赖测试人员的编程能力与经验，耗时漫长。在追求快速交付的敏捷与DevOps模式下，脚本开发速度常常跟不上版本的迭代节奏。 5. 无法有效处理非结构化内容传统自动化技术主要针对结构化的UI或API进行验证，对于图像内容、语音识别、视频播放等非结构化结果的正确性验证几乎无能为力，仍需依赖耗时的人工检查。
[P7] 自动化测试概述：传统自动化测试发展到智能测试：因此，智能测试是自动化测试范式在AI技术驱动下的必然发展方向。智能测试在传统自动化测试的基础上，通过深度集成人工智能、机器学习及大数据分析等关键技术，使测试过程具备自学习与自适应能力，能够针对测试生成、执行、分析与维护等多个环节进行动态优化，突破了传统自动化测试的局限，实现了从执行自动化到认知自动化的飞跃。

[P9] 智能测试概述：智能测试：结合AI算法和测试数据等，对测试多环节进行针对性优化的测试方法，主要指在持续追求提升研发交付效能下，人工智能技术在测试领域的应用，具有更强的适应性和响应能力。三大核心智能特性 • 自学习能力：通过分析历史测试的数据、代码变更、用户行为等信息，持续积累知识。 • 自适应能力：执行中可自主应对应用程序的界面或逻辑微小变更，具备脚本 “自愈”性。 • 自主决策能力：在测试生成、执行调度、结果分析等环节可自主判断与决策。

[P11] 智能测试四大优化环节：智能测试用例生成系统自动分析需求、代码与历史数据，智能生成覆盖全面的测试用例，显著提升测试效率与覆盖质量。测试用例执行与优化在执行过程中，系统能够实时感知应用变化，自动调整执行路径与元素定位，具备“自愈” 能力。同时根据执行反馈，优化测试用例的优先级与结构，提升回归效率。缺陷自动检测与智能修复通过图像识别、日志分析等技术，系统能够自动识别与验证缺陷，并对可预测的常见问题（如元素定位失败、数据格式异常）提供自动修复建议或执行脚本修正。测试报告生成与分析通过数据挖掘与AI技术，实现测试报告的自动生成与深度分析，更能基于历史数据进行智能风险预测，为软件质量评估与测试决策提供精准的数据支持和可视化指引。
[P12] 环节一：测试用例生成：①基于模型：利用UML/状态机等模型描述系统行为，自动生成测试用例与路径。该方法适用于多组件业务流程的集成测试及具有明确状态转移的系统测试。 ②基于自然语言处理：基于需求文档或文本描述，利用自然语言处理技术自动生成测试场景与用例。适用于需求转测试用例、功能测试生成，以及支持单元测试的快速构建。 ③基于强化学习：通过强化学习与奖励机制优化测试策略与路径探索，更适用于安全测试、稳定性测试以及复杂交互场景测试。 ④基于视觉与交互记录：通过录制用户操作自动生成可复用的GUI测试脚本，适用于Web/移动端GUI功能测试、UI回归与差异检测，并可支持快速原型验证与脚本生成。智能测试的测试用例生成4种技术，即基于模型的测试用例生成、基于自然语言处理的测试用例生成、基于强化学习的测试用例生成和基于视觉与交互记录的测试用例生成。针对不同的应用场景，使用不同的方式进行测试用例的生成会更加合适。

[P13] 基于模型的测试用例生成：基于模型的测试用例生成（Model Based Testing，MBT）该方法通过构建系统行为的形式化模型（如状态机、流程图），自动生成高覆盖率的测试用例与指令，显著提升生成效率并减少人工干预。核心流程： 1. 根据需求构建系统行为模型 2. 测试引擎基于模型自动生成可执行用例 3. 执行用例并观察记录实际结果 4. 将实际结果与模型预期进行比较判定基于模型的测试用例生成流程图
[P13-图1 课件第 13 页的图] 流程图 开始 → 基于需求构建形式化模型 → 基于模型生成测试用例与预期结果 → 执行测试用例 → 实际结果与预期结果比对。 分支1：一致 → 测试通过 → 测试完成。 分支2：不一致 → 失败根因分析 → 诊断结论。 诊断结论分支： 1. 环境/数据问题 → 调整后重新测试 → 回到“执行测试用例”。 2. 模型不准确 → 返回修正模型 → 回到“基于需求构建形式化模型”。 3. 发现系统缺陷 → 提交缺陷修复 → 验证修复并确认通过 → 测试完成。
[P14] 基于自然语言处理的测试用例生成：基于自然语言处理的测试用例生成该方法利用文本分析、信息抽取和词嵌入等技术，将需求文档自动转化为结构化测试场景，显著提升生成效率和准确性，减少人工转述成本。核心流程： 1. 需求解析：通过NLP/LLM解析需求文档，提取测试要素 2. 建模生成：应用测试设计方法构建场景，自动生成用例草稿 3. 人工校准：人工审核调整用例，补充完善测试覆盖 4. 输出交付：格式化输出最终用例基于自然语言处理的测试用例生成流程图

[P15] 基于强化学习的测试用例生成：基于强化学习的测试用例生成（Reinforcement Learning，RL）通过模拟软件运行过程，不断尝试不同的测试路径，并根据奖励信号调整测试策略，以找到最优的测试路径。核心流程： 1. 观察决策：获取系统状态，根据策略选择测试动作 2. 执行反馈：执行动作，记录新状态与奖励 3. 策略优化：基于反馈更新策略模型 4. 迭代输出：重复执行至终止条件，输出优化后的测试路径。基于强化学习的测试用例生成流程图

[P16] 基于视觉与交互记录的测试用例生成：基于视觉与交互记录的测试用例生成通过记录用户在界面上的操作（如点击、输入、滑动等）并自动转化为可执行的测试脚本的技术。该方法通常依赖于计算机视觉、UI 元素识别和交互事件捕捉技术，实现从“用户操作视频”到“结构化测试用例”的自动转换。核心流程： 1. 操作录制：录制用户操作，捕获交互事件与界面快照 2. 元素识别：识别UI元素与视觉特征，生成结构化操作步骤 3. 脚本生成：基于结构化步骤生成可执行测试脚本 4. 验证优化：验证脚本回放准确性，必要时调整识别逻辑 5. 集成应用：验证通过后集成至测试套件，形成可复用的测试脚本基于视觉与交互记录的测试用例生成流程图

[P17] 环节二：测试用例执行与优化：测试用例执行与优化技术，主要包括测试脚本自动调整、测试脚本智能调度和动态资源分配与并行执行三类技术。在测试用例执行与优化阶段，智能测试通过智能调度、自愈环境和精准测试，实现高效、可靠的自动化测试执行与反馈。当测试用例在持续集成环境中执行时，智能测试系统能够实时感知被测应用程序的变更，例如用户界面UI元素的微小变动。一旦因这些非功能性变更导致测试脚本失败，系统能自动识别失败原因，并调用自我修复机制，如重新定位元素、调整等待策略或动态更新脚本，从而绕过无关紧要的干扰，继续执行后续测试，显著提升了测试套件的健壮性和稳定性。测试用例执行与优化的三类技术

[P18] 环节三：缺陷自动检测与修复：• 基于图像识别的缺陷修复：通过计算机视觉与深度学习技术自动检测UI界面中的布局错位、颜色偏差等视觉异常，实现UI测试的自动化。 • 基于代码识别的缺陷修复：结合深度学习与大语言模型（如CGM），直接分析代码结构与语义，自动识别空指针异常、数组越界等代码缺陷并生成修复补丁，实现从缺陷定位到修复的自动化闭环。 • 基于异常日志识别的缺陷修复：利用自然语言处理技术对系统日志进行语义分析与模式识别，自动提取异常信息、定位故障根因，并通过机器学习预测潜在问题，实现日志驱动的问题诊断与预警。 • 基于故障注入的缺陷修复：通过混沌工程主动注入系统故障（如服务中断、网络延迟），观察系统在异常条件下的行为与自愈能力，验证系统弹性并暴露潜在风险点，提升系统的健壮性与可靠性。缺陷自动检测与修复的四类技术

[P28] 测试用例生成实验总结：核心差异：测试生成逻辑。基于自然语言 • 优点：深度灵活，可覆盖边界条件与复杂逻辑，生成高质量、可维护的代码资产，便于集成CI/CD 流程。 • 缺点：对使用者逻辑思维与编程能力要求较高，无法模拟真实用户的复杂界面交互。 • 使用场景：适合开发人员在编码阶段进行单元测试、接口测试及代码质量保障。基于视觉与交互记录 • 优点：直观易用，可快速创建端到端业务流程测试，适合回归测试与验收测试。 • 缺点：本质是操作路径复现，数据驱动测试需重复录制，难以高效覆盖大量输入组合。 • 使用场景：适合测试人员在系统交付阶段进行UI 验证、业务流程保障及用户视角的功能验证。
