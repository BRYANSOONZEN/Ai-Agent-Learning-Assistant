# 视频转文字 + 课件问答（原型）

> 设计：`docs/计划-个人学习助手.md` 第 8 节。
> **这是独立的原型脚本，还没有接进平台**（后端和页面都没有改）。验证日期：2026-11-11（4.5 节为同日加测的计算机课程）。

## 一、做什么

老师上传的视频，内容主要在讲解的声音里。助手要能根据视频回答学生的问题，先要把声音变成带时间点的文字：

```
视频 → 检查大小和时长 → 取出声音 → 本机语音识别（中文 SenseVoice / 英文 Whisper，每句带时间）→ 老师在句子上校对
     → 合并成 30～60 秒一段（带前一段最后一句 + 标知识点）
     → 学生提问 → 选内容（必要时先改写检索词）→ 大模型回答并标出“视频 01:35”
```

| 文件 | 作用 |
|---|---|
| `video_to_text.py` | 检查、识别（SenseVoice 或 Whisper）、分段、重叠、标知识点，输出 JSON；`--from-json` 只重新分段和标知识点 |
| `text_utils.py` | 切词和知识点匹配，两个脚本共用 |
| `ask_video.py` | 选内容、调大模型回答、标时间点 |
| `验证结果/` | 下面第四节每一步的原始输出 |

## 二、怎么用

```bash
pip install torch torchaudio --index-url https://download.pytorch.org/whl/cpu   # 默认引擎 SenseVoice 要用
pip install funasr                  # 第一次运行下载 SenseVoice 模型约 940 MB
pip install faster-whisper          # 备用引擎 Whisper；small 模型约 480 MB
python video_to_text.py 视频.webm --chapter 1 --out 结果.json --lang zh     --terms "边界值,等价类,测试用例" --kps "边界测试值的选取;边界错误的成因"
python video_to_text.py 校对后.json --from-json --chapter 1 --out 结果.json --kps "..."   # 老师校对后重新分段、标知识点
python ask_video.py 结果.json "边界值为什么要取边界外侧的值？"
```

- `--terms`：这一章的专业词。接进平台后，由章节标题和知识点名称**自动生成**，老师不用填。
- `--kps`：这一章的知识点名称，分号分隔。接进平台后从知识点表取。
- `--lang`：讲解的语言（zh / en）。
- `--engine`：识别引擎，默认 `auto`：**按课程语言自动选，中文用 SenseVoice，英文用 Whisper**；也可以手动指定 `sensevoice` 或 `whisper`。
- `ask_video.py` 的 API key 从环境变量 `LLM_API_KEY` 或 `application-local.yml` 读，不会打印出来。

## 三、规则

| 规则 | 值 | 为什么 |
|---|---|---|
| 文件大小 | ≤ 200 MB | 和后端上传限制一致 |
| 时长 | ≤ 60 分钟 | Whisper 约 1 倍速，SenseVoice 约 5 倍速（4.6 节）；更长的请老师分段上传 |
| 没有讲解声音 | 明确提示老师 | 只有背景音乐的视频识别不出东西，要截帧识别画面文字或请老师补说明 |
| 静音过滤 | 必须开 | 关掉后，Whisper 遇到纯音乐会编出“字幕by……”这种不存在的句子 |
| 分段 | 满 30 秒且在句末切；满 60 秒不管在哪都切 | 回答能精确到时间点，也方便检索 |
| 重叠 | 每段带上前一段的最后一句，单独存放 | 答案跨在两段交界上时检索也能拿全；这一段自己的时间点不变 |
| 标知识点 | 名称原样出现，或名称某一部分有区分度的词 60% 以上出现 | 问题提到某个知识点时，标了它的段加分（4.5 节实测有效） |
| 交给模型的内容 | 一章文字 ≤ 3000 字就全部给；更长才检索前 3 段 | 关键词检索对不上同义词（见下） |
| 改写检索词 | 走检索时，先让模型把问题改写成视频所用语言的关键词 | 中文问英文课什么都检索不到；问“预防”对不上“降低发生率”（4.5 节） |
| 老师校对 | 在**句子**上改，改完重新分段和标知识点 | 专业词会识别错，也会影响检索和标签 |
| 识别在哪做 | 本机 | 不把老师的视频发给外部服务 |
| 识别引擎 | 按课程语言自动选：中文 SenseVoice，英文 Whisper | SenseVoice 快 4～6 倍，中文专业词更准；英文不如 Whisper（4.6 节） |
| 每小段时长 | SenseVoice 的静音检测每段最长 15 秒 | 时间点更细，又不至于把句子切碎 |
| 语气词 | 去掉“嗯、呃”和句首“啊”，合并“你你”这类重复 | SenseVoice 会把它们全记下来，干扰检索 |

测试视频（都来自 Wikimedia Commons，开放许可，只用于测试，**视频本身不放进仓库**）：

| 编号 | 视频 | 时长 | 许可 | 作者 |
|---|---|---|---|---|
| V1 | 中文維基百科教學頻道第一章.ogv | 3:18 | CC BY-SA 3.0 | 香港分子 |
| V2 | 《台傳媒新聞》20180919 中醫大附醫軟式輸尿管鏡技術 無傷口粉碎腎結石.webm | 2:37 | CC BY 3.0 | 台傳媒ETVNEWS |

环境：本机 CPU，faster-whisper 1.2.1，small 模型，int8；问答用 deepseek-flash。

### 4.1 上传检查

| 输入 | 结果 |
|---|---|
| 210 MB 的文件 | 拒绝：“文件 210 MB，超过 200 MB” |
| 61 分钟的音频 | 拒绝：“视频 61 分钟，超过 60 分钟，请分段上传” |
| 不是视频的文件 | 拒绝：“文件无法读取，可能不是视频或已经损坏” |
| V1、V2 | 通过 |

**测出的问题，已改**：一开始是先读视频、后看大小，超大或损坏的文件会直接报错崩掉，没有提示。改成先看大小，并捕获读取错误。

### 4.2 没有讲解声音的视频（V1）

V1 是录屏 + 背景音乐 + 字幕，没有人讲话。

- 开静音过滤：识别出 0 句。**这是对的**。脚本现在会明确提示“没有识别到讲解声音”。
- 关静音过滤：识别出“字幕by索兰娅”，这句话是模型编出来的。所以静音过滤必须开着。

### 4.3 识别效果（V2）

| | 不加专业词 | 加专业词（肾结石、输尿管、泌尿部等 7 个） |
|---|---|---|
| 识别耗时 | 183 秒（0.86 倍速） | 175 秒（0.9 倍速） |
| 句数 / 段数 | 42 句 / 3 段 | 16 句 / 4 段 |
| 标点 | 没有 | 有 |
| 专业词写对次数（肾结石、输尿管、泌尿、附医） | **0 次** | **10 次** |

加专业词明显有效，但仍有错（“肾脏”写成“圣杖”，“肾结石”有时写成“圣洁时”）。模拟老师校对，改了 17 处错字。

### 4.4 问答（V2，真实模型）

同一组问题，校对前、校对后各跑一次：

| 问题 | 回答（校对后） | 依据时间点 | 对不对 |
|---|---|---|---|
| 这种手术是从哪里进去的？ | 从尿道放入输尿管鞘和软式输尿管镜，伸到肾脏里 | 00:38 | 对 |
| 怎么预防肾结石？ | 多补充水分、多喝水，饮食均衡营养，限制盐分和动物性蛋白摄取 | 02:07 | 对 |
| 李小姐做了几次手术？ | 五次 | 00:38 | 对 |
| 瀑布模型是什么？（视频里没有） | 课件里没有讲到这个问题 | — | 对，没有乱编 |

每次约 1～2 秒。校对前的 4 个回答也都对：模型能按上下文理解同音错字。

**过程中测出的问题，都已改：**

1. **只取 2 段时，“怎么预防”漏掉了 02:07 那段**：同分的段被挤掉了。
2. **改成取 3 段也漏**：问的是“预防”，视频里说的是“降低……发生率”，关键词对不上。现在的做法：一章文字 ≤ 3000 字就全部交给模型；更长时才检索，并给常见词降低分量。
3. **有一次回答是空的**：这个模型的“思考”也算在输出长度里，上限给 300 不够，改成 4096，空回答时再试一次。后端里早就是 4096，原型漏了。
4. **读 key 报 401**：配置里的值带引号，没有去掉。

### 4.5 计算机课程（2026-11-11 加测）

前面两个视频不是计算机课，又加测了两门计算机课程，并在过程中加上了“重叠”“标知识点”“改写检索词”。

| 编号 | 视频 | 时长 | 许可 | 用法 |
|---|---|---|---|---|
| V3 | MIT《The Missing Semester》Lecture 7 - Debugging and Profiling (2020)，英文 | 54:13 | CC BY 3.0（Wikimedia Commons） | 识别文字放进 `验证结果/7`，注明出处 |
| V4 | 南京大学 2022《操作系统：设计与实现》第 1 讲（蒋炎岩），中文 | 99:24 | **archive.org 转存，没有标注许可** | 只在本机测试；仓库里只放统计、标签和短摘录（`验证结果/9`） |

**上传检查**：两个完整视频都被拦下。V3 是“248 MB，超过 200 MB”；V4 是“282 MB，超过 200 MB”，而且长 99.4 分钟，也超过 60 分钟。之后模拟老师分段，各取 10 分钟再处理：V3 取 00:00–10:00，V4 取 03:00–13:00。

**识别**（本机 CPU，small 模型）：

| | V3 英文 10 分钟 | V4 中文 10 分钟 |
|---|---|---|
| 识别耗时 | 484 秒（1.24 倍速） | 726 秒（0.83 倍速） |
| 句 / 段 | 97 / 12 | 138 / 14 |
| 专业词提示的效果 | 几乎没有：debugging、printf、logging 不加提示也认对 | 这一段讲课程安排和学术诚信，没出现进程、系统调用这些词，看不出效果 |
| 典型错误 | printf → “printfd”，Unix → “unique”，/var/log → “slash bar lock” | 中英混说（academic integrity、class meeting）都能识别 |

**分段之后要做的三件事，都是这次实测发现后加上的：**

1. **标知识点改了三次**：
   - **第一次**：一句“什么是操作系统”被同时标上“定义、为什么学、历史”三个知识点。原因是这些名称都带“操作系统”。改法：三分之一以上知识点都有的词不参与匹配，“什么”“为什么”这类疑问词也不算。
   - **第二次**：“课程安排和学术诚信”一个都没标上。原因是名称太长，“学术诚信”全中了也只占 4/8。改法：名称按“和、与、及、顿号”拆开，任何一部分对上就算。
   - **第三次**：讲学术诚信的三段被标成“程序和状态机”。原因是拆开后的“程序”太常见，一提就算对上。改法：只剩一个词的部分不能单独算数。
   - **结果**：V4 只有讲点名和学术诚信的 4 段被标上，V3 的标签和内容都对得上。
   - **还没解决**：标签只看字面。医学视频那段讲的是“降低肾结石的发生率”，没有标上“肾结石的预防”。要靠老师校对时确认。
2. **标知识点对检索有用**：V3 用英文问“How do terminals show colored log output?”，没有标签时选中的三段都不对；有了标签，相关的三段全部选中。
3. **中文问英文课，一段也检索不到**：关键词检索只能匹配同一种语言。改法：走检索时，先让模型把问题改写成视频所用语言的关键词，包括同义说法。这样多一次调用，每次提问总共约 1.5～4 秒。

**重叠**：这几组问题的答案都没有跨在两段交界上，看不出差别。它是为了防止答案被切成两半，代价只是每段多一句话。

**问答（真实模型）：10 个问题全部答对**

| 视频 | 问题 | 回答要点 | 时间点 |
|---|---|---|---|
| V3 | printf 调试有什么问题？（中文问英文课） | 输出太多，可能超出所需 | 01:34 ✓ |
| V3 | 终端里的彩色日志是怎么实现的？ | 改日志格式的颜色；底层是在文字前后加转义字符 | 05:03、05:52 ✓ |
| V3 | 系统日志一般放在哪个目录？ | /var/log（识别结果是“slash bar lock”，模型按上下文理解对了） | 07:26 ✓ |
| V3 | GDB 怎么设置断点？（这段没讲） | 课件里没有讲到 | ✓ 模型懂 GDB，但没有自己补充 |
| V3 | 同样两个问题用英文问 | 同上 | ✓ |
| V4 | 这门课上课点名吗？为什么？ | 不点名，希望把时间用在更正确的地方 | 03:31 ✓ |
| V4 | 什么是学术诚信？ | 完整性，发自内心对自己更高的要求 | 04:34 ✓ |
| V4 | 如果觉得自己不太会编程怎么办？ | 花时间补一补 | 02:13 ✓ |
| V4 | 什么是系统调用？（这段没讲） | 课件里没有讲到 | ✓ |

**耗时**：
- 分段、重叠、标知识点：每次 12 毫秒，可以忽略。
- 慢的是识别，约 1 倍速，但只在上传时做一次。
- 学生提问：全部给模型时 1～2 秒；走检索时，加上改写检索词，约 3.5～4 秒。

**这次测出并改掉的问题，除了标知识点那三处：**
- 用 `python -I` 运行时，找不到同目录的 `text_utils.py`，已改为启动时把脚本所在目录加进去。
- 英文句子拼在一起时没有空格。
- 原来的切词只适合中文，英文单词被拆成两个字母一组。
- 提问耗时没有算上改写检索词那一次调用。


### 4.6 换成 SenseVoice（2026-11-11）

**为什么换**：Whisper 太慢了，15 分钟的视频要 12～18 分钟。它慢主要是因为输出文字时一个字一个字地生成。SenseVoice 是阿里开源的语音识别模型，一次输出整句，而且专门为中文训练过。

**怎么接**：`--engine sensevoice`（默认）或 `whisper`（备用）。后面的分段、重叠、标知识点、问答都没有改。接入时加了两处：

- **每小段最长 15 秒**：SenseVoice 先用静音检测（fsmn-vad）把有人说话的部分切成小段，不限时平均 28 秒一段，最长 47 秒，回答里的时间点会偏差十几秒。限到 10 秒又切得太碎，句子容易被拦腰切断。15 秒是折中。
- **去掉语气词**：SenseVoice 会把“嗯、呃”一字不落记下来，10 分钟里有 68～77 个。现在去掉“嗯、呃”和句首的“啊”，“你你”“就就”这类口吃重复合并成一个，“谢谢”“看看”这类正常叠词不动。

**结果**（同一台笔记本 CPU，同样的 10 分钟片段）：

| | Whisper small | SenseVoice（接入后） |
|---|---|---|
| 操作系统课（中文）识别耗时 | 712～726 秒 | **112 秒（5.4 倍速）** |
| MIT 调试课（英文）识别耗时 | 484～487 秒 | **101 秒（5.9 倍速）** |
| 医学视频（中文，2:37） | 175～183 秒 | **56 秒** |
| 15 分钟的中文课（推算） | 约 18 分钟 | **约 3 分钟** |
| 模型大小 | 约 480 MB | 936 MB（另加静音检测 1.7 MB） |

**中文专业词**（医学视频，写对的次数）：

| 词 | Whisper | Whisper + 专业词提示 | SenseVoice（不用提示） |
|---|---|---|---|
| 肾结石 | 0 | 1 | **4** |
| 输尿管 | 0 | 5 | 5 |
| 肾脏 | 0 | 0 | **4** |

**问答（真实模型）**：

| | 操作系统课（中文） | MIT 调试课（英文） |
|---|---|---|
| 结果 | **4 题全对**。“点名”题比 Whisper 版答得更全：说出了不点名的原因 | **4 题对 3 题**。“系统日志放在哪个目录”答成了“没有讲到” |

**英文比 Whisper 差**：

- printf 一次都没认出来，写成了“print thebugging”。
- /var/log 写成了“fo core like last bar log”，比 Whisper 的“slash bar lock”还乱。
- 句号只有 Whisper 的一半，几句话常连成一句，检索就找不到那段。

**结论**：中文课用 SenseVoice 明显更好，英文课 Whisper 更好。组内决定**按课程语言自动选**（`--engine auto`，默认）：中文 SenseVoice，英文 Whisper。

**自动选的验证**：不指定引擎，中文医学视频自动用 SenseVoice（2:37 用了 34 秒），英文 MIT 2 分钟片段自动用 Whisper（107 秒）。英文这次加了专业词提示，printf 写对了 3 次；但之前 10 分钟那次加了同样的提示仍写成“printfd”，提示有帮助但不稳定。

**安装**：`pip install torch torchaudio --index-url https://download.pytorch.org/whl/cpu` 和 `pip install funasr`。第一次运行会从 Hugging Face 下载模型。

### 4.7 还没解决的

- **同义词和跨语言**：已经用“先让模型改写检索词”解决了这次测到的情况（4.5 节），但改写也可能漏掉。内容多了以后可以换成能理解意思的检索（向量检索）。
- **画面上的文字**（板书、幻灯片）还没处理：V1 这种只有字幕没有讲解的视频，要截帧做文字识别。
- **没有接进平台**：上传后自动处理、后台任务和进度、老师校对页面、存表、助手调用，都还没做。
- **英文课更慢**：英文课用 Whisper，约 1 倍速，15 分钟的英文课约 12 分钟。
- **标知识点只看字面**：同义说法标不上（如“降低发生率”对“预防”），要靠老师校对时确认标签。
- 一共测了 4 个视频（2 个计算机课，各 10 分钟片段），问了 14 个问题，样本小。结论只说明“流程跑得通、哪些地方要注意”，不是正式评测。
